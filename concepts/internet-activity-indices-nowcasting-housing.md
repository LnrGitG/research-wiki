# Индексы интернет-активности для nowcasting рынка жилья

Research design из диалога с Google AI Mode (авг 2026) + критическая адаптация
под доступные для РФ источники. Финальный выбор в диалоге — **FAVAR-MIDAS**:
квартальные макропоказатели Росстата прогнозируются через еженедельные
интернет-индексы (nowcasting с опережением публикации на ~2 мес).

## Три стратегии (из диалога)

| Вариант | Метод | Суть |
|---|---|---|
| А | MIDAS + поиск | Nowcasting регистраций сделок (Росреестр/Дом.РФ) поисковыми интентами vs AR-бенчмарк |
| Б | FAVAR + медиа | «Информационные волны» (100+ рядов → PCA) самостоятельно разгоняют спрос |
| В | SVAR + сентимент | Трансмиссия ставки ЦБ → новостной сентимент → аренда (быстро) / покупка (вязко) |

Выбор: **вариант 2 = MIDAS/FAVAR-MIDAS на официальной статистике** — сильная
математическая работа; SVAR остаётся как расширение при появлении коммерческих
баз (ЦИАН/Сбер).

## Спецификация модели

Низкочастотный блок Y^Q (Росстат/ЦБ, квартально): P^Q_new (цена первички),
P^Q_rent (аренда), V^Q_new (ввод жилья или ДДУ), I^Q_R (ключевая ставка,
средняя за квартал).

Высокочастотные шоки Z^W (weekly): FX^W (USD/RUB, CNY/RUB), IR^W (ОФЗ, RUONIA
— ожидания по ставке).

Цифровые следы X^W → PCA → 4 фактора:
1. **F_Demand_New^W** — ипотечные/первичковые запросы («купить новостройку»,
   «семейная ипотека», «дду застройщик»)
2. **F_Demand_Rent^W** — арендные интенты («снять квартиру долгосрочно»)
3. **F_Media_Hype^W** — просмотры 50–100 каналов о недвижимости
4. **F_Sentiment^W** — новостной сентимент СМИ (Gemini/NL API)

Уравнение (экспоненциальный полином Алмона B(L^{1/m};θ)):

P^Q_t = α + Σβ_i·P^Q_{t−i} + Σδ_j·I^Q_{R,t−j} + Φ_FX(L)·FX^W_{t·m}
        + Γ_F(L)·F_Demand_New^W_{t·m} + ε_t

Гипотезы: (1) интернет-индексы обладают опережающей силой для квартальных
показателей; (2) асимметрия сегментов — шоки неопределенности быстрее бьют
по аренде (гибкие цены), первичка реагирует на субсидированные программы.
Академическая новизна — behavioral pass-through: девальвация → паника в медиа
→ бегство в недвижимость; рост ставки → обвал спроса на покупку + переток в аренду.

## Семантическое ядро запросов (3 интент-группы)

| Группа | Маркеры | Минус-слова |
|---|---|---|
| А: инвестиционный спрос | купить новостройку, старт продаж ЖК, ДДУ, льготная/семейная/ИТ ипотека | вторичка, снять, посуточно |
| Б: потребительский (аренда) | снять квартиру долгосрочно, аренда без посредников, снять однокомнатную | посуточно, на сутки, купить, ипотека |
| В: защитно-панический | куда вложить рубли, недвижимость защитный актив, забрать вклад купить квартиру | — |

Методы расширения семантики: (1) **эмбеддинги** — базовые маркеры через
sentence-transformers → автопоиск синонимов в логах («первичка», «дду»,
«однушка»); (2) **детекция аномалий** — в дни шоков ЦБ фиксируются фразы с
максимальным относительным приростом vs исторической нормой → добавляются в
фактор.

**RII (Relative Interest Index)** — нормировка от сезонности и доли поисковика:
RII_Rent^W = Σ Clicks(фразы_аренды)^W / Σ Clicks(все_запросы_недвижимость)^W.
Доля вместо абсолютов чистит общерыночный тренд.

## Пайплайн (4 этапа)

Сбор (парсеры, еженедельно) → NLP-разметка (NL API скрининг + LLM-скоринг
по сущностям: Rubel_Volatility, CB_Rate_Expectations, Real_Estate_Primary,
Rental_Market; шкала −1..+1 × magnitude) → хранение и выравнивание в weekly
матрицу → PCA → MIDAS (R `midasr` / Python statsmodels) → out-of-sample
валидация (опережение публикации Росстата).

## ⚠️ Критическая адаптация под РФ (мои правки к диалогу)

Диалог предлагает стек Google Cloud, но для российского среза он частично
нереализуем. Замены:

1. **Поиск: Яндекс Wordstat API вместо Search Console.** GSC требует владения
   сайтом («данные партнёров-классифайдов» недоступны); Google — лишь 35–40%
   поиска РФ. У нас уже есть клиент `research-wiki/scripts/wordstat_api.py`:
   monthly+weekly с 2018-01, daily ~60 дней, 100 запр/час. Это ровно нужные
   high-frequency ряды, но на доминирующей платформе (~65%). Selection bias
   диалога разворачивается: смещение будет у Google-, а не Яндекс-индекса.
2. **YouTube: Data API v3, не Analytics API.** Retention/shares доступны только
   владельцам каналов; публично — views/likes/comments по видео списка каналов
   через search+videos endpoints. Контроль structural break замедления YT
   2024–25: параллельно VK Video/Rutube как панель сравнения платформ.
3. **Инфраструктура: без BigQuery/Dataproc.** Национальный срез — десятки тысяч
   статей/мес; VPS + SQLite достаточно до 100× большего объёма.
   Существующие хранилища уже закрывают блоки модели:
   - target Y^Q: `data/rosreestr_deals.db` (сделки/ДДУ по регионам и кварталам,
     2024q1–2026q2), rosstat_construction.db (цены, ввод), regions_panel.db
   - I^Q_R, FX^W: cbr-выгрузки (cron по вторникам)
   - прототип сентимента: `data/housing_sentiment_index.csv`
   - LLM-скоринг: прямой REST к Gemini (GEMINI_API_KEY) работает
4. **MIDAS vs MF-BVAR:** вики-кластер nowcasting (Anttonen 2018 — dashboards
   Google Search в seasonal BVAR; Zubarev MFBVAR РФ) даёт альтернативу:
   mixed-frequency BVAR с entropic tilting как робастness-чек MIDAS.

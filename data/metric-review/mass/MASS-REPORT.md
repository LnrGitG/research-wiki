## Разбор «53% расхождений» контроля (18 из 34)

Заголовочная доля обманчива; разбор по типам:

**11 из 18 — null-vs-value, несущественные.** GLM возвращает null там, где
Astra ставит значение (accumulation: null vs single_period; base: null vs
level). Это не ошибка, а консервативность GLM при сомнении — по промпту так
и задумано. Рецепт: при применении null наследует значение контрольной
модели, если поле не запрещено.

**7 из 18 — содержательные, все про accumulation (ввод мощностей vm*) и одна
база ИЦП.** Это «Ввод мощностей: Ткани/Асфальтобетон/Пиво…» — серия из
сотен однотипных рядов, где Росстат публикует и за период, и накопленным
итогом; без сверки конкретного листа однозначного ответа нет. Направлены в
needs_review (см. ниже), НЕ блокируют применение остальных 1 822.

Один случай интересен в обратную сторону: y477110132 (ИЦП по видам
деятельности) — GLM сказала same_period_last_year (что совпадает с
паспортом партии 3: «в % к соотв. периоду прошлого года»), Astra —
previous_period. Здесь прав скорее GLM; тоже в needs_review со ссылкой на
паспорт.

## Главная ценность прогона: 334 рядов накопительного итога

GLM корректно опознала year_to_date у 334 метрик, у которых накопительность
видна прямо в имени: «Промпродукция, накопленным итогом: …» (десятки
стройматериалов: цемент, ЖБИ, кирпич), housing_input_*_cumulative, okv,
drpotr/druotr. Эвристика шага 1 (enrich_stat.py) этого класса не видела
вовсе — это прямое расширение словаря детерминированных правил: имя
содержит «накопленным итогом»/«cumulative» → accumulation=year_to_date.
После сверки выборки этих рядов правилом можно закрыть без LLM.

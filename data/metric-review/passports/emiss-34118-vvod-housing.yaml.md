# Паспорт метрики: emiss_34118_vvod_housing_oper

- **metric_code:** `emiss_34118_vvod`
- **name_ru:** Введено в действие общей площади жилых домов (оперативные данные)
- **источник:** ЕМИСС, ID страницы 34118 (fedstat.ru), endpoint `POST /indicator/dataGrid.do?id=34118`
- **URL:** https://www.fedstat.ru/indicator/34118
- **unit:** ths_sqm (тыс. м² общей площади), unit_id=16
- **frequency:** месячная (freq_id=5) + накопленно с начала года (те же колонки периода)
- **годы доступных данных:** 2024–2026 (оперативный разрез короткий)
- **разрезы:** регион (95: ФО + субъекты, РФ-агрегата НЕТ), номенклатура (14 видов)
- **дата скрейпа (факт):** 2026-09-19 (выгрузка dataGrid с ВМ YC)
- **регламент публикации:** не позднее 14-го числа месяца, следующего за отчётным
- **факт этой версии:** 19.09.2026 → lag 5 дней относительно 14.09.2026
- **двойной счёт:** строки ФО исключать при агрегировании
- **сверка с итоговым:** 2024 оперативно 112 157 тыс. м² против итога 107 768
  (metric 59263/Росреестр-сводка) → оперативный сдвиг +4,1%
- **связи:** [[emiss-construction-scraping-202609]]; канонический годовой ряд —
  core.metric 1148 (vztgr, 2000–2025) и metric 22 (vdppzd, 1990–2021)

## Правила загрузки в БД
1. metric_code = `emiss_34118_vvod`, tags = [emiss, operational, housing]
2. frequency_id=5; period_start = 1-е число отчётного месяца;
   накопленные значения — отдельный sub_dimension `basis: cumulative`
3. значения по субъектам (region_id по справочнику), ФО-строки НЕ грузить
   (восстановимы агрегированием; в разрезе нет РФ-агрегата)
4. каждая выгрузка — новый release (release_label с датой и lag);
   дубли по (metric_id, region_id, period_start, sub_dimension) — upsert
   с сохранением release_id последней выгрузки
5. при сверке с итоговым рядом расхождение >5% — quality_flag
   `operational_premium`

## Регламент фиксации метрик (общий порядок)
1. **Регистрация в core.metric:** metric_code, name_ru, unit, frequency,
   tags=[источник, operational/final], status=active/pilot.
2. **Паспорт в registry:** status preliminary → active после этапа 2
   (сверка с первоисточником).
3. **Каждая выгрузка = отдельный release:** release_label с датой выгрузки,
   ingested_at = фактическая дата, published_at = регламентная дата
   (или null, если паспорт не утверждён).
4. **Контроль отставания:** если дата выгрузки позже регламентной —
   quality_flag `late_release` + лаг в днях; систематическое отставание
   источника фиксируется в паспорте.
5. **Сверка версий:** при поступлении уточнённых значений за тот же период —
   observation_status: operational → revised → validated; старое значение
   сохраняется (release-история), перезапись запрещена.
6. **Приёмка:** после загрузки — COUNT по (year, month), контрольная сумма
   суммы субъектов, сравнение с прошлой выгрузкой (дельта > 5% по месяцу —
   алерт).

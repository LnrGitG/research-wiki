# db/ — схема и служебные скрипты целевой базы

Файлы перенесены 18.09.2026 из служебного бакета `agent-vm-exchange`, где они
существовали в единственном экземпляре и были уязвимы к потере (бакет
используется как канал исполнения команд на ВМ и может быть перезаписан).

## schema/schema-live.sql

**Актуальная схема** целевой базы `research_wiki`, снятая `pg_dump --schema-only`
из живого PostgreSQL на ВМ 18.09.2026 (обновлено после удаления legacy-таблицы).
1 330 строк, 20 таблиц, 1 представление, схемы `core`, `meta`, `derived`,
`pipeline`, `marts`.

**Это источник правды по структуре.** Здесь есть `core.observation_v2` (целевая
таблица наблюдений, 16 колонок) и представление `core.v_datalens_observations`
для DataLens.

Восстановить структуру с нуля:

```bash
psql -h localhost -U wiki -d research_wiki -f db/schema/schema-live.sql
```

## schema/ddl-initial.sql

**Первоначальный DDL** рубежа Ф2 (17.09.2026, 300 строк) — то, с чего начиналась
построение базы. Сохранён исторически, потому что именно этот файл лежал в
бакете; он же показывает, как эволюционировала схема.

Оговорка: в нём описана таблица `core.observation`, а не `observation_v2`.
Хронология такова: сначала строили `observation` (рубеж 3, 551 022 строки),
затем при гармонизации появилась `observation_v2`, в которую перенесли всё
содержимое (2 174 291 строка). **18.09.2026 legacy-таблица `observation`
удалена** — проверено, что ни одно значение не потеряно (разбор:
`queries/legacy-observation-removal.md`). Актуальна только `observation_v2`.

Для восстановления структуры использовать `schema-live.sql`, не этот файл.

## schema/load-regions.sql

Загрузка справочника регионов (102 записи) и алиасов написаний (432 алиаса).
Применяется после `schema-live.sql` — справочник нужен для привязки наблюдений.

```bash
psql -h localhost -U wiki -d research_wiki -f db/schema/load-regions.sql
```

## scripts/mirror_v2.py

Скрипт миграции SQLite → PostgreSQL, работавший на ВМ (рубеж Ф3). Читает базы из
того же бакета и переносит таблицы в `staging`. Историческая ценность: показывает
соответствие имён (`<база>__<таблица>`) и преобразование типов SQLite → PostgreSQL.

В повседневной работе не нужен — миграция выполнена, базы живут в PostgreSQL.

## Что здесь намеренно отсутствует

- **Секреты.** Ни в одном файле нет паролей и ключей; доступ к бакету в
  `mirror_v2.py` получается динамически через метаданные ВМ
  (`169.254.169.254/computeMetadata/...`).
- **Файлы данных.** SQLite-базы (1,35 ГБ) остаются в бакете `wiki-research/data/db/`
  и в PostgreSQL; в git их не кладём.

Hermes Agent — FAQ по командам и эксплуатации

Практический справочник по управлению агентом, субагентами, навыками, бандлами, инструментами, памятью, curator и провайдерами LLM. Особый акцент — на исследованиях экономики, финансов, эконометрике на R/Python и работе на слабом VPS: 1 ГБ ОЗУ, 20 ГБ диска.

Формат: справочник + лучшие практики + шаблоны конфигурации
Важно: ниже приведён практичный, рекомендуемый синтаксис команд Hermes Agent. В конкретной сборке префиксы или имена команд могут немного отличаться (/, !, hermes, CLI/GUI). Первый шаг в любой новой установке: /help, /doctor, /status.

Базовые команды

Как быстро проверить, что агент работает? 
/status
/doctor
/logs tail --level=error

/status показывает текущую модель, провайдера, память и активные задачи. /doctor проверяет окружение: ключи, инструменты, доступ к диску, сеть.

Как посмотреть все команды? 
/help
/help agents
/help memory
/help tools
/help curator
Как включить подробный режим отладки? 
/logs level debug
/logs tail
/status --verbose

Для слабого VPS не держите debug постоянно: логи могут занять диск.

Как остановить текущую задачу? 
/task stop
/subagent stop all
/tools kill hung-process

Агенты: создание, выбор, шаблоны

Как создать агента для экономики, финансов и эконометрики?

Рекомендуется принцип: один агент — одна роль. Не делайте одного универсального агента для всего: лучше отдельные профили для кода, сбора данных, анализа и отчётов.

Полезные команды управления агентами

/agent export econ-analyst --path ./backups
/agent import ./backups/econ-analyst

Какие шаблоны агентов полезны для исследований?

План исследования, источники, гипотезы, обзор литературы.

Проверка качества, источников, логики и воспроизводимости.

Субагенты: делегирование и изоляция задач

Как создать субагента? 
/subagent create macro-fetcher \
  --role "Сбор макроданных" \
  --tools web_search,file_write \
  --memory none \
  --max-turns 8 \
  --model cheap

Субагент хорош для узкой задачи: собрать данные, проверить код, подготовить черновик отчёта, рассчитать один показатель. На 1 ГБ ОЗУ лучше запускать строго одного субагента за раз.

Как запустить задачу субагента? 
/subagent run macro-fetcher "Собери годовые данные по инфляции и ключевой ставке за 2010–2025 годы"
/subagent logs macro-fetcher
/subagent stop macro-fetcher
Как ограничить субагента? 
/subagent create safe-reader \
  --tools file_read,web_search \
  --no-shell \
  --read-only \
  --max-cost low \
  --max-turns 5

Лучшие практики: не давать субагенту shell без необходимости; ограничивать число шагов; запрещать запись вне рабочей папки; использовать дешёвую модель для рутины.

Типичная схема делегирования 
Основной агент: аналитик-координатор
├── Субагент 1: сбор данных
├── Субагент 2: очистка данных
├── Субагент 3: эконометрическое моделирование
└── Субагент 4: curator / проверка качества

На слабом VPS не используйте параллельный запуск; используйте последовательный конвейер.

Навык — это переиспользуемая способность: метод анализа, шаблон отчёта, сценарий работы с данными, инструкция по R/Python, работа с конкретным источником, способ проверки модели. 

/skills list

/skills enable econometrics-basics
/skills disable web-browsing
/skills remove deprecated-skill

После установки проверьте:

/skills enable econometrics

Инструменты: file, shell, Python, R, web

Как посмотреть и включить инструменты? 
/tools list
/tools enable file_read file_write python r web_search
/tools disable browser shell
/tools status
Как безопасно настроить shell? 
/tools config shell.mode allowlist
/tools config shell.workdir /workspace
/tools config shell.timeout 120
/tools config shell.allowed_commands "ls,cat,head,tail,grep,python3,Rscript,pip list,git status"

Для VPS с экономическими исследованиями лучше разрешать только нужные команды: python3, Rscript, файловые утилиты, архиваторы. Не давайте полный shell без жёсткой необходимости.

Как настроить Python и R? 
/tools enable python r
/tools config python.binary python3
/tools config python.venv /workspace/.venv
/tools config python.timeout 180
/tools config r.binary Rscript
/tools config r.timeout 180
/tools config output.max_lines 400

Для тяжёлых расчётов ставьте лимит времени и максимальный объём вывода. Иначе одна регрессия или большой вывод может подвесить слабого агента.

Как ограничить веб-доступ? 
/tools enable web_search http_request
/tools config web.allow_domains "cbr.ru,rosstat.gov.ru,fred.stlouisfed.org,imf.org,worldbank.org,oecd.org"
/tools config web.max_pages 3
/tools config web.timeout 20
Политика минимальных привилегий

/tools deny shell.sudo
/tools deny file_write:/etc

Curator: контроль качества и проверка результатов

Что такое curator?

Curator — это надзорный контур: он проверяет ответы агента, качество кода, наличие источников, корректность интерпретации моделей и соблюдение ограничений. Для экономических задач крайне полезен. 

/curator status
/curator enable
/curator disable
/curator review last
/curator report
Как настроить правила Curator? 
/curator add_rule "Все количественные выводы должны указывать источник и дату данных"
/curator add_rule "Не давать инвестиционных рекомендаций без явного дисклеймера"
/curator add_rule "Код R/Python должен быть воспроизводимым и сохранять артефакты в /workspace"
/curator add_rule "Перед выводом показывать: метод, данные, ограничения, риски"
/curator list_rules
Минимальный набор правил для экономики и финансов 
1. Указывай источник данных и период.
2. Различай факт, оценку и прогноз.
3. Для моделей указывай спецификацию, выборку и диагностические тесты.
4. Не подменяй корреляцию причинностью без оговорок.
5. Проверяй единицы измерения: проценты, индексы, миллиарды, сезонность.
6. Не давай индивидуальных инвестиционных рекомендаций.
7. Сохраняй код, данные и лог расчёта в рабочей папке.

LLM-провайдеры: Ollama, LM Studio, AI Studio, Yandex и другие

Базовые команды провайдеров 
/provider list
/provider add ollama --url http://127.0.0.1:11434
/provider add lmstudio --base-url http://127.0.0.1:1234/v1
/provider add yandex --auth env:YANDEX_API_KEY
/provider use yandex
/provider test
Как подключить Ollama? 
/provider add ollama --url http://127.0.0.1:11434
/provider use ollama
/config set llm.model qwen2.5:0.5b
/provider test

Если Ollama работает не на VPS, а на другом сервере/ПК, укажите его адрес, например: http://192.168.1.10:11434 или через защищённый туннель.

Как подключить LM Studio? 
/provider add lmstudio \
  --base-url http://127.0.0.1:1234/v1 \
  --api-key lmstudio
/provider use lmstudio
/provider test

LM Studio обычно удобен как локальный сервер на более мощной машине. Для VPS с 1 ГБ ОЗУ запускать тяжёлую локальную модель внутри того же сервера нежелательно.

Как подключить Yandex / AI Studio / другие API? 
/provider add yandex --auth env:YANDEX_API_KEY
/provider use yandex
/config set llm.model yandex-gpt-pro
/provider test

Ключи лучше хранить в переменных окружения или секретах системы, а не в memory.md и не в открытых конфигах.

Как экономить токены и ресурсы? 
/config set llm.fallback cheap-model
/config set limits.max_context_tokens 2048
/config set limits.max_output_tokens 512
/config set memory.compact_before_task true

Практика: дешёвая модель делает сбор и первичную сортировку, сильная модель — только финальный анализ, интерпретацию и отчёт.

Работа на слабом VPS: 1 ГБ ОЗУ, 20 ГБ HDD

Главная рекомендация

Не запускайте тяжёлую локальную LLM на этом же VPS. Оптимально: агент и инструменты живут на VPS, а LLM — внешний API или удалённый Ollama/LM Studio на более мощной машине.

Профиль конфигурации для 1 ГБ ОЗУ 
/config profile create vps-low
/config use vps-low
/config set llm.provider remote-api
/config set limits.max_context_tokens 2048
/config set limits.max_output_tokens 512
/config set tools.parallelism 1
/config set memory.backend sqlite
/config set logs.level warn
/config set tools.output_max_lines 300
/config save
Системные советы для VPS
ДействиеЗачем
Добавить swap 2–4 ГБСнижает риск OOM, но на HDD будет медленно.
Один активный агент/субагентЭкономия ОЗУ и CPU.
Лёгкие Python/R-зависимостиМеньше памяти и диска.
SQLite/DuckDB вместо больших CSV в памятиЭкономия ОЗУ.
Ограничить логи20 ГБ HDD быстро заполняются.

Если всё же хочется локальную модель 
# Только если нет другого варианта.
# Модель должна быть очень маленькой и квантованной.
/config set llm.provider ollama
/config set llm.model qwen2.5:0.5b
/config set limits.max_context_tokens 1024
/config set limits.max_output_tokens 256

На 1 ГБ ОЗУ даже 0.5B–1.5B может работать нестабильно. Лучше использовать внешний API.

soul.md, agent.md, memory.md

Где редактировать файлы агента? 
/agent edit soul.md

Что писать в soul.md? 
# Soul
Ты — осторожный исследователь экономики и финансов.
Твоя цель — точность, воспроизводимость и полезность выводов.

Ценности:
- факты важнее впечатлений;
- источники обязательны;
- неопределённость указывается явно;
- нельзя выдавать корреляцию за причинность.

Стиль:
- сначала вывод, затем обоснование;
- таблицы и код — компактно;
- без инвестиционных рекомендаций без дисклеймера.
Что писать в agent.md? 
# Agent
Имя: econ-analyst
Роль: эконометрика, макроанализ, финансовые данные.

Алгоритм работы:
1. Уточни вопрос и критерий успеха.
2. Составь план.
3. Собери данные и проверь источник.
4. Подготовь код на R/Python.
5. Выполни расчёт и сохрани артефакты.
6. Проверь устойчивость и ограничения.
7. Сформируй краткий отчёт.

Ограничения:
- рабочая папка: /workspace
- не выполнять опасные системные команды
- не хранить секреты в памяти
- при ошибке — остановить задачу и сообщить причину
Что писать в memory.md? 
# Memory
## Пользователь
- Предпочитает краткие выводы и таблицы.

Резервные копии и перенос

Что резервировать? 
/agent export --all --path ./backups
/memory export --path ./backups/memory.json
/bundles export --all --path ./backups
/config export --path ./backups/config.json
Автоматический бэкап 
# Пример cron-задания, если поддерживается CLI:
0 3 * * * hermes backup run --path /opt/hermes/backups --profile vps-low

Храните минимум 3 копии: локальная, вне сервера, архив перед крупными изменениями.

Безопасность

Базовые правила 
/tools policy show
/tools deny shell.sudo
/tools deny shell.rm_rf
/tools deny file_write:/etc
/tools deny file_write:/root
/config set secrets.storage env

Не храните ключи в memory.md, agent.md, логах или открытых файлах проекта.

Что запрещать инструментам? 
rm -rf /
shutdown
reboot
chmod 777
curl | sh
wget | bash
dd if=/dev/zero
любые операции вне /workspace без явной необходимости

Диагностика и типовые проблемы

Проблема Проверка Решение
Агент не отвечает /status, /doctor, /logs tail Проверить провайдера, API-ключ, сеть, лимиты.
Не хватает памяти htop, free -m, /status Уменьшить контекст, отключить параллелизм, использовать внешний LLM.
Инструмент не запускается /tools status, /doctor Проверить разрешения, пути, allowlist, зависимости.
Память раздута /memory show, /memory stats /memory compact, удалить лишнее, ограничить TTL.
Модель галлюцинирует /curator review last Добавить правила об источниках, снизить temperature, требовать данные.
Диск быстро заполняется df -h, du -sh * Очистить логи, кэш, артефакты, ограничить вывод.

/status
/doctor

Итоговые лучшие практики

1. Один агент — одна роль

Разделяйте координатора, сборщика данных, эконометриста и curator.

2. Минимальные инструменты

Включайте только то, что нужно задаче: файл, Python, R, web_search.

3. Компактная память

Храните только устойчивые факты, решения, источники и ограничения.

4. Curator обязателен

Для экономики и финансов он снижает галлюцинации и ошибки интерпретации.

5. Внешняя LLM для слабого VPS

1 ГБ ОЗУ — не место для тяжёлой локальной модели.

6. Всё сохраняйте в артефакты

Код, данные, таблицы, графики и логи должны быть воспроизводимы.

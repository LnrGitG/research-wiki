# В Западно-Южно-Центральном округе начинается строительство индивидуального жилья с использованием спутниковых снимков. Техническая документация 

№ 1. Введение 

Бюро переписи населения США изучает возможность использования спутниковых изображений для измерения активности в области строительства новых жилых домов для Обзора строительства (SOC). Оценки строительства жилья на одну семью в Западно-Южно-Центральном округе (WSC) с использованием спутниковых данных публикуются в качестве экспериментального продукта данных<sup>1</sup>, который послужит подтверждением концепции использования спутниковых изображений в качестве метода сбора данных для SOC. 

Для мест выдачи разрешений в выборке SOC образцы разрешений на строительство новых жилых домов отбираются ежемесячно, а сбор данных осуществляется путем опросов представителей на местах или посещений объектов. Благодаря новому методу сбора данных спутниковые изображения для подмножества мест в выборке SOC для подразделения WSC собираются ежемесячно, что позволяет наблюдать за всем новым жилищным строительством в выбранных местах, а не за выборкой проектов нового жилищного строительства. Данные о застройке, полученные со спутникового изображения, затем объединяются с данными исследования SOC для выбранных мест, не собранных с помощью спутника в подразделении WSC, для расчета оценки ежемесячного строительства жилья на уровне подразделения. 

# 2. Предыстория SOC 

## 2.1 Пример дизайна 

Структура выборки Обследования строительства состоит из трех этапов: (1) подвыборка первичных единиц выборки (ПЕВ) Текущего обследования населения (CPS) 2004 года, которые представляют собой земельные территории (группы округов, городов или поселков в пределах штата), которые представляют всю территорию Соединенных Штатов; (2) выбор разрешенных/неразрешенных территорий; и (3) ежемесячный выбор разрешений. Зоны разрешений соответствуют офису разрешений на строительство (BPO). В настоящее время не планируется никаких изменений в структуре выборки для внедрения сбора спутниковых данных.  Дополнительную информацию о схеме выборки SOC см. на странице методологии SOC. 

## 2.2 Сбор данных 

Основным новшеством в продукте экспериментальных данных является использование спутниковых изображений в качестве метода сбора данных по всей территории, покрытой BPO, для подмножества BPO в текущей выборке SOC. При наблюдении за всей территорией, охваченной BPO, заключительный этап отбора выборки, этап выборки разрешений, исключается, расширяя выборку за счет включения всех разрешений из выбранного BPO. Для первоначальной реализации сателлитов выбранные BPO представляют собой саморепрезентативные места из саморепрезентативных ПЕВ, поэтому их совокупные веса выборки на первом и втором этапе равны единице.

# 3. Область применения 

## 3.1 Географический 

Текущий набор BPO, собираемый с помощью спутника, представляет собой саморепрезентативные BPO из саморепрезентативных PSU в текущей выборке SOC для Западно-Южно-Центрального округа (Дивизион 7). Учитывая ограниченное использование сбора спутниковых данных в настоящее время, оценка рассчитана только на уровне отдела. Это обеспечивает более детализированную с географической точки зрения таблицу, чем текущая оценка добычи, которая учитывает только региональный уровень. 

## 3.2 Тип конструкции 

Оценка ограничивается началом строительства жилья. Несмотря на то, что для SOC собирается множество элементов данных, основное внимание в этом продукте уделяется новостройкам, поскольку их легко наблюдать по спутниковым снимкам и они соответствуют определению SOC начала жилищного строительства. Сметы для других этапов строительства потребуют дальнейшей разработки и являются областью будущих исследований. 

## 3.3 Тип жилого дома 

Этот продукт ограничен домами на одну семью, поскольку каждое наблюдение соответствует одной единице жилья, и оценку можно получить, просто подсчитав количество наблюдаемых запусков. 

Кроме того, дома на одну семью обычно строятся на территориях, где расположены другие дома на одну семью. Эти жилые кварталы на одну семью легко идентифицировать на спутниковых снимках и используются в модели типа здания, описанной в разделе 5.1, чтобы ограничить подсчет застроек районами, которые, вероятно, будут содержать дома на одну семью. Однако в начале строительства многоквартирные здания может быть трудно отличить от офисного здания или больницы. Оценка начала строительства многоквартирного жилья по спутниковым снимкам – еще одна область будущих исследований. 

# 4. Коллекция изображений

<mark>Области интереса (AOI) для сбора спутниковых данных выбираются из существующей выборки мест выдачи разрешений SOC с упором на районы со значительной активностью строительства частных домов. Эти AOI включают в себя инкорпорированные территории (города, поселки и деревни), места, определенные переписью (CDP), округа и некорпоративные территории.</mark> **<mark>Места</mark>** <mark> относятся к конкретным ограниченным территориям, которые либо включены в соответствии с законодательством штата со своими местными органами власти, либо, в случае CDP, некорпоративны, но идентифицированы для статистических целей.</mark> **<mark>Округи</mark>** <mark>, с другой стороны, представляют собой более крупные административные единицы, охватывающие несколько мест, а также некорпоративные территории. Для определения точных границ этих AOI используются шейп-файлы Census Tiger/Line. Геометрия округов извлекается из файла округа США, а геометрия мест — из файлов мест, относящихся к конкретному штату.</mark> **<mark>Некорпоративные территории</mark>** <mark>округа определяются путем объединения геометрии округа с включенными местами, определяемыми посредством пространственного соединения с использованием данных BPS и шейп-файлов Tiger/Line, оставляя некорпоративную часть в качестве нового AOI для некорпоративной территории этого округа.</mark> 

<mark>После того, как геометрия установлена, она отправляется поставщику изображений для дополнения в соответствии с требованиями спутниковых задач. Поставщик упрощает AOI, уменьшая количество вершин, чтобы общее количество вершин для проекта оставалось ниже определенного предела. Кроме того, если область интереса слишком мала для удовлетворения требований задачи, ее можно объединить с более крупной близлежащей областью интереса. В некоторых случаях поставщик может удалить такие территории, как аэропорты, государственные и федеральные парки, военные базы и водоемы, где жилищное строительство невозможно. Мы проверяем измененные AOI вместе с поставщиком, чтобы подтвердить, что любые изменения уместны. Эти дополнения не влияют на исходные используемые AOI</mark> 

<знак>для отчетности по данным. Наконец, перед началом выполнения задачи поставщик и поставщик изображений оценивают, можно ли захватить области в течение требуемого периода времени.</mark> 

В идеале спутниковые снимки должны быть сделаны в первый день месяца, следующего за базисным. Однако погодные условия могут сделать AOI или части AOI недоступными для наблюдения со спутника именно в этот день. Более длинное окно сбора изображений увеличивает вероятность получения пригодных для использования спутниковых изображений. Текущее окно задач спутников установлено с 25<sup>th</sup> исходного месяца по 5<sup>th</sup> числа следующего месяца. 

№ 5. Измерение жилья начинается со спутниковых снимков 

Начало строительства жилья на одну семью идентифицируется по спутниковым изображениям с использованием серии моделей сверточной нейронной сети (CNN) и этапов постобработки. Чтобы идентифицировать этапы построения, присутствующие на изображении, мы используем модель внимания U-Net, которая интегрирует механизм внимания в свою структуру кодера-декодера.  Это усиливает внимание модели к актуальному пространственному будущему и особенно полезно для различения этапов строительства на загроможденных спутниковых изображениях.  Выходные данные маски прогнозирования модели представляют собой файл изображения Geo-TIF в оттенках серого, который состоит из разных цветов в оттенках серого для каждого пикселя, представляющего разные категории интересов. Затем процесс поиска больших двоичных объектов извлекает кластеризованные или связанные пиксели одной и той же классификации, называемые большими двоичными объектами. Это обеспечивает четкий результат этапа строительства объекта без необходимости использования сторонних данных об участках.  Каждый объект представляет собой одно из следующих значений: бассейн, крышу, конкретную стадию строительства здания, землю или растительность. ## 5.1 Исключения 

Чтобы уменьшить шум в результатах поиска больших двоичных объектов, применяется несколько процессов фильтрации для удаления начальных больших двоичных объектов, которые могут оказаться ложноположительными. Это включает в себя наложение начальных объектов на полигоны контуров зданий, доступные на Картах Bing, и исключение начальных объектов, которые перекрываются с существующими зданиями. Кроме того, стартовые пятна накладываются на известные дороги с использованием данных Tiger/Line Road Data за 2023 год, чтобы исключить старты, перекрывающиеся с дорогами.

Вторая модель CNN применяется к спутниковым изображениям для классификации территорий по типу здания ( <mark>отдельный дом на одну семью, пристроенный дом на одну семью, многоквартирный дом и нежилой дом</mark>). При определении типа здания на большой территории изображения обычно содержат слишком много объектов, поэтому используется модель DeepLabV3+ с архитектурой модели ResNet50.  Эта комбинация оказалась эффективной при обработке сложных городских объектов путем группировки различных мелких объектов.  Застройки, попадающие в районы, классифицируемые как многоквартирные или нежилые, исключаются из спутниковых оценок для односемейных застроек. 

## 5.2 Классификация бизнеса и дополнительные исключения 

Специальные бизнес-правила применяются для интерпретации хода строительства путем анализа переходов между прогнозами предыдущего и текущего месяцев. Эти правила помогают определить статус строительства для каждого объекта недвижимости на основе логики, определенной в Таблице 1. 

Например, если прогнозировалось, что в предыдущем месяце участок будет находиться на этапе ЗЕМЛЯ, а в текущем месяце указано РАСХОДЫ, присваивается бизнес-класс СТАРТ, что указывает на то, что строительство перешло от подготовки земли к активной застройке. Аналогичным образом, переход от РАСКОПАНИЙ к ФУНДАМЕНТУ будет указывать на дальнейший прогресс, поэтому будет присвоен бизнес-класс В ПРОГРЕССЕ. 

Большие двоичные объекты предыдущего месяца сопоставляются с большими двоичными объектами текущего месяца с использованием геометаданных и алгоритмов сопоставления, учитывающих любые различия в размерах между большими двоичными объектами в разные месяцы. После применения бизнес-правил прогнозы агрегируются в определенном месте. Эта агрегация дает оценку количества начатых строительных работ на конкретной территории. 

Модель может предсказать некоторый шум из-за облачности, плохой видимости или ограниченного солнечного света в зимние месяцы. Эти случаи могут привести к расхождениям в том, что следует соблюдать. Для соответствующей корректировки этих несовпадающих областей выполняется этап постобработки. Например, если прогнозируется, что на территории в течение 3 месяцев будет крыша, вероятность того, что она станет растительностью, крайне маловероятна. Поэтому мы модифицируем результат так, чтобы он был от крыши до крыши, что переводит MISSCLASSIFIED BACKWARDS в категорию EXIST. 

Смена времен года является дополнительным источником шума в прогнозах модели. Дома с деревьями поблизости можно классифицировать как РАСТИТЕЛЬНОСТЬ при наличии листьев, но классифицировать как КРЫШУ после того, как листья опадают. Это приводит к категоризации НАЧАЛО ЗАВЕРШЕНИЯ, названной так потому, что проект переходит от стадии предварительного строительства к завершенной крыше за один месяц. Подавляющее большинство BLOB-объектов, обозначенных как START COMPLETION, представляют собой шум. Однако, хотя переход от стадии подготовки к строительству (ФОН, ЗЕМЛЯ или РАСТИТЕЛЬНОСТЬ) к крыше в течение месяца встречается редко, он все же происходит, чаще всего в районах, где множество строительных проектов происходит близко друг к другу, например, в новом районе, и поэтому его нельзя полностью игнорировать. Следовательно, BLOB-объекты START COMPLETION, которые лежат в пределах того же геохеша (более подробную информацию о геохешах см. в разделе 5.3 ниже), что и BLOB-объект, отнесенный к категории START, включаются в оценку стартов, а все остальные исключаются.

## 5.3 Вменение

Как и в случае с другими методами сбора данных, на спутниковых снимках могут отсутствовать данные, чаще всего из-за облачности. Может отсутствовать весь AOI или, что чаще, отсутствует только часть AOI. Кроме того, по определенной территории могут отсутствовать данные в течение нескольких месяцев подряд. 

Новое жилищное строительство обычно неравномерно распределено по территории АОИ, которая может занимать целый город или округ. Обычно он локализован в небольшом количестве районов, при этом множество новых домов строится близко друг к другу. Когда наблюдается частичный AOI, вместо применения механизма отсутствующих данных на уровне AOI мы применяем локализованный подход с использованием геохэшей. Geohash — это общедоступная система геокодирования, позволяющая определять географические области в иерархической пространственной структуре. Количество символов в хеше представляет размер: 6-значный Geohash больше по площади по сравнению с 7-символьным Geohash. Для вменения мы делим AOI на составляющие его 7-значные геохеши (153 x 153 м). На этом более детализированном географическом уровне как предположение о равномерном распределении строительной деятельности в текущем месяце, так и предполагаемая корреляция активности в последовательных месяцах более правдоподобны, чем на уровне АОИ. 

Когда мы сталкиваемся с недостающими данными для всего Геохеша или части Геохеша, мы извлекаем из самых последних наблюдаемых данных для этого Геохеша, чтобы получить вмененное значение для недостающих данных. Если в текущем месяце наблюдается менее 50% геохеша, начальное значение геохеша устанавливается равным максимальному количеству начал геохеша, наблюдаемых в текущем месяце, а геохэш начинается с предыдущего (или последнего наблюдаемого) месяца.  Если в текущем месяце наблюдается не менее 50 % геохеша, начало текущего месяца корректируется путем деления наблюдаемого начала на долю наблюдаемого геохеша. Например, если было обнаружено 75% геохеша и в наблюдаемой области было обнаружено 3 запуска, окончательное значение запусков для геохеша будет рассчитано как 3/0,75 = 4 запуска. 

## 5.4 Настройка окна захвата 

Настройка окна захвата используется для корректировки постимпутированных значений разницы в днях между датами изображения. Из-за длинного окна захвата изображений количество дней между наблюдениями могло варьироваться от 20 до 42 дней. Мы корректируем предполагаемые старты для данной области по отношению количества дней в целевом месяце к количеству дней между наблюдениями. 

Например, если изображение за май было снято 1 июня, а изображение за июнь — 4<sup>th</sup> июля, при расчете оценок июня между изображениями будет 33 дня, а в июне будет только 30 дней. Поэтому июньская оценка будет умножена на 30/33, чтобы внести поправку на промежуток времени между наблюдениями. 

# 6. Оценка 

В настоящее время оценки начала строительства жилья SOC рассчитываются как сумма части обследований разрешений на использование (SUP), рассчитанной на основе данных об уровне разрешений с помощью отдельного оценщика коэффициентов, и части неразрешений (NP), рассчитанной как взвешенная сумма наблюдаемого нового строительства из выбранных неразрешенных территорий. См. раздел «Сбор данных» технической документации SOC. 

Однако оценки, полученные по спутниковым снимкам, относятся к уровню BPO и не могут использоваться с нашим текущим оценщиком, который объединяет данные на уровне разрешений. Таким образом, оценка начала одной семьи WSC для месяца _t_ ( 𝑆̂𝑆𝑂𝐶,𝑡) представляет собой гибридную оценку, объединяющую оценки уровня места, полученные по спутниковым снимкам ( 𝑆𝑆𝐴𝑇,𝑡) с модифицированной версией используемой в настоящее время отдельной 

оценщик соотношения для неспутниковых мест SUP (𝑆̂𝑆𝑈𝑃_𝑁𝑆,𝑡) и NP-части оценки ( 𝑆̂𝑁𝑃,𝑡), которая остается неизменной. 

𝑆̂𝑆𝑂𝐶,𝑡 = 𝑆𝑆𝐴𝑇,𝑡 + 𝑆̂𝑆𝑈𝑃_𝑁𝑆,𝑡 𝑆̂𝑁𝑃,𝑡 

𝑆̂𝑆𝑈𝑃_𝑁𝑆,𝑡 — это сумма 14 оценок коэффициента, состоящая из ежемесячных оценок за последние двенадцать месяцев и двух дополнительных оценок коэффициентов, которые объединяют месяцы 13–18 в единую оценку, а месяцы 19–60 – в окончательную оценку. Каждая оценка соотношения имеет форму единиц, разрешенных в период 𝑚̃, а 𝑌𝑚̃ — это стоимость квартир, разрешенных в рамках обследования разрешений на строительство (BPS), в период 𝑚̃ и 𝑚̃ может быть один месяц или совокупность месяцев.

Модификация, внесенная в текущий оценщик SUP для этой оценки подразделения WSC, заключается в добавлении калибровочного коэффициента PSU, так что взвешенное значение выборочных разрешений за данный месяц из неспутниковых мест в каждой выбранной PSU равняется общему количеству разрешений за этот месяц из неспутниковых мест в этом PSU из BPS. См. Приложение А для получения дополнительной информации о процессе оценки. 

# 7. Достоверность данных 

## 7.1 Ошибка выборки 

Ошибка выборки для неспутникового компонента оценивается с использованием модифицированного метода полувыборки, который в настоящее время используется для SOC. Спутниковая часть оценки не содержит ошибки выборки, поскольку все выбранные спутниковые места являются саморепрезентативными, и сбор спутниковых данных предпринимается для всех областей охвата для выбранных мест. 

## 7.2 Ошибка, не связанная с выборкой 

Ошибка, не связанная с выборкой, включает все источники ошибок, кроме ошибки выборки, которые вносят вклад в общую ошибку оценки. Как вспомогательная, так и неспутниковая часть оценки строительства жилья WSC на одну семью подвержены ошибкам, не связанным с выборкой. К ним относятся ошибки охвата, ошибки сбора, ошибки измерения, ошибки вменения, ошибки из-за отсутствия ответов и другие ошибки обработки. Хотя ошибка, связанная с выборкой, не измеряется напрямую, процедуры контроля качества применяются во всех процессах обработки спутниковых и неспутниковых данных, чтобы минимизировать ошибки, связанные с выборкой. 

## 7.3 Отсутствие ответа 

Текущий метод корректировки на отсутствие ответов для начала строительства жилья SOC учитывает поздние отчеты о начале строительства, которые, как ожидается, будут получены с задержкой до двенадцати месяцев, путем умножения оценки начала строительства жилья SUP на поправочный коэффициент неполного покрытия отсутствия ответов (NUAF), рассчитанный на уровне региона. Оценка строительства жилья WSC на одну семью использует ту же методологию, но применяется на уровне подразделения для неспутникового компонента оценки, используя только неспутниковые выборочные места при расчете NUAF. 

№ 8. Недопущение раскрытия информации 

Текущий метод предотвращения раскрытия информации SOC по подавлению ячеек будет продолжать использоваться, при необходимости, для оценок запуска WSC для одной семьи. Бюро переписи населения проверило этот продукт, чтобы обеспечить надлежащий доступ, использование и защиту конфиденциальных исходных данных от раскрытия (номер одобрения Совета по рассмотрению раскрытия информации (DRB): CBDRB-FY25-0086).

## A.1 Общая структура 

<mark></mark> **<mark>Архитектура кодировщика-декодера</mark>** <mark>очень полезна для таких задач, как семантическая сегментация, поскольку она эффективно балансирует извлечение признаков и восстановление пространственного разрешения. В этой архитектуре</mark> **<mark>кодер</mark>** <mark>концентрируется на извлечении абстрактных функций высокого уровня из входного изображения, таких как формы, шаблоны и семантическая информация, путем постепенного понижения дискретизации пространственных измерений и применения глубоких сверточных слоев. Затем</mark> **<mark>декодер</mark>** <mark>восстанавливает пространственные детали, гарантируя детальные прогнозы за счет повышения дискретизации объектов до исходного разрешения. Эта комбинация позволяет модели одновременно фиксировать глобальный контекст и сохранять локальные детали.</mark> 

<mark>Одним из ключевых преимуществ этой архитектуры является ее способность изучать функции в различных масштабах. Кодер сжимает изображение, позволяя модели захватывать большие восприимчивые поля и извлекать глобальную информацию, а декодер объединяет это с локальными функциями для получения детальных результатов сегментации. Такое многомасштабное обучение особенно полезно для обработки объектов разных размеров на изображении. Кроме того, пропуск соединений или объединение функций между кодером и декодером облегчают сохранение мелких пространственных деталей, что приводит к более четким границам и более точным прогнозам.</mark> 

<mark>Структура кодер-декодер также эффективна в вычислительном отношении. Уменьшая пространственные размеры на этапе кодирования, модель может сосредоточиться на изучении сложных семантических шаблонов, требуя при этом меньше вычислительной мощности. Затем декодер использует это компактное представление для восстановления значимой пространственной информации. Более того, гибкость этой архитектуры позволяет легко адаптироваться к различным задачам, таким как семантическая сегментация, анализ медицинских изображений или сегментация экземпляров, путем интеграции различных магистральных сетей (например, ResNet или MobileNet) в качестве кодировщиков, в зависимости от требований задачи и вычислительных ограничений.</mark>

<mark>Еще одним важным преимуществом является его устойчивость к шуму и небольшим наборам данных. Структура узкого места в кодировщике вынуждает модель изучать основные функции, что помогает уменьшить переобучение зашумленных данных. Кроме того, предварительно обученные кодировщики можно использовать для передачи знаний из больших наборов данных, что обеспечивает эффективное обучение даже при ограниченном количестве размеченных данных. Эта архитектура также может включать в себя механизмы внимания, повышающие способность фокусироваться на наиболее важных областях изображения, тем самым улучшая качество сегментации.</mark> 

<mark>В целом архитектура кодировщика-декодера представляет собой элегантное и эффективное решение для семантической сегментации, сочетая глобальный контекст, сохранение локальных деталей, вычислительную эффективность и гибкость, что делает ее популярным выбором для задач плотного прогнозирования.</mark> 

## A.2 Модель этапа строительства 



_Рис. 2. Модель этапа строительства с использованием архитектуры Attention U-Net._ 

<mark>Эта модельная диаграмма представляет</mark> **<mark>архитектуру Attention U-Net</mark>** <mark>, предназначенную для задач семантической сегментации. Архитектура принимает входное изображение размером 256x256x3 и обрабатывает его через структуру кодера-декодера, дополненную воротами внимания для фокусировки на соответствующих областях. Кодер состоит из сверточных слоев (свертки 3x3 с активацией ReLU) и слоев максимального пула (2x2) для постепенного понижения входных данных и извлечения иерархических функций. Пропуская соединения между кодировщиком и декодером, можно сохранить пространственные детали за счет непосредственной передачи объектов из кодера в соответствующие слои декодера.</mark> 

<mark>Декодер повышает дискретизацию карт объектов с помощью транспонированной свертки (2x2) и уточняет их с помощью сверточных слоев, постепенно реконструируя карту сегментации в соответствии с входным разрешением. Ворота внимания (AG) установлены вдоль соединений пропуска, чтобы подчеркнуть наиболее важные функции и при этом подавить фоновый шум. Эти ворота динамически учатся концентрироваться на ключевых регионах, умножая входящие карты признаков на веса внимания, вычисляемые на основе контекстуальной важности. На выходе слой свертки 1x1 отображает уточненные функции в маску сегментации 256x256x7, где каждый пиксель соответствует одному из семи выходных классов. Использование шлюзов внимания обеспечивает точную сегментацию, усиливая фокус модели на критических областях и одновременно уменьшая помехи от нерелевантных частей изображения, что делает эту архитектуру особенно эффективной для задач, требующих детального и точного попиксельного прогнозирования. Дополнительную информацию о Attention U-Net см. в Jing (2019).</mark> 



## A.3 Модель типа здания 



_Рис. 3. Модель типа здания с использованием архитектуры семантической сегментации._ 

<mark>Диаграмма модели представляет собой архитектуру семантической сегментации, предназначенную для обработки входного изображения, в нашем случае спутникового изображения, с помощью структуры кодера-декодера. Процесс начинается с подачи входного изображения в кодировщик, который использует магистраль ResNet50 для извлечения признаков. Кодировщик фиксирует иерархические представления объектов, начиная от деталей низкого уровня, таких как края и текстуры, до семантических функций высокого уровня. Для улучшения многомасштабного обучения функциям архитектура включает в себя модуль Atrous Spatial Pyramid Pooling (ASPP) внутри кодера. Этот модуль состоит из свёрток 1x1 для точечного извлечения объектов, свёрток 3x3 с различной степенью расширения (6, 12 и 18) для захвата объектов в разных пространственных масштабах, а также глобального пула изображений для кодирования контекста по всему изображению. Результаты этих операций объединяются и проходят через свертку 1x1, чтобы обеспечить компактное и значимое представление объектов.</mark>

<mark>Декодер дополняет кодировщик, восстанавливая пространственное разрешение и уточняя прогнозы. Низкоуровневые функции более ранних уровней кодера интегрируются в декодер через пропускные соединения, гарантируя сохранение мелких пространственных деталей. Эти низкоуровневые функции сначала обрабатываются с использованием свертки 1x1, чтобы уменьшить размеры их каналов и сделать их совместимыми с высокоуровневыми функциями модуля ASPP. Декодер повышает дискретизацию функций высокого уровня в четыре раза, объединяя их с функциями низкого уровня посредством конкатенации. Дополнительное уточнение достигается за счет серии сверток 3x3 и дальнейшей повышающей дискретизации, что гарантирует, что выходная маска сегментации соответствует разрешению исходного входного изображения.</mark> 

<mark>Наконец, модель выводит маску попиксельной сегментации, которая прогнозирует класс каждого пикселя входного изображения, например здания, дороги или растительности. Эта архитектура сочетает в себе глобальный и локальный контекст, что позволяет делать точные прогнозы с высоким разрешением. Его конструкция использует сильные стороны как кодера для извлечения абстрактных признаков, так и декодера для пространственной реконструкции, что делает его хорошо подходящим для сложных задач семантической сегментации. Дополнительную информацию о семантической сегментации см. Kou et al. (2022).</mark>

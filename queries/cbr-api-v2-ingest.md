# Загрузка блоков API ЦБ в БД v2 (денежные агрегаты, индексы курса, ИЖК)

Дата: 2026-09-23. Скрипт: `scripts/cbr_api_v2_ingest.py`. Источник: универсальный API ЦБ (`www.cbr.ru/dataservice`), без ключа.

## Контекст

Схема v2 в живой БД — `core.observation_v2` (уникальный индекс на metric/region/freq/period/source/release/assessment/sub_dimension) + `core.release` (run-версионность: каждый запуск = новый release_id, ревизии не перезаписывают, а добавляют версию). Отдельной таблицы `load_run` и схемы `v2_stage` в живой БД нет — роль run-журнала выполняет `core.release`, роль staging не нужна при прямых идемпотентных вставках с `ON CONFLICT DO NOTHING`. Это решение зафиксировано как отступление от раннего протокола `queries/db-v2-reload-spec.md` (тот описывал проектную схему; фактически реализована упрощённая).

## Принятые решения

1. **Релиз вместо load_run/v2_stage.** Ранний протокол v2 предполагал staging-схему и load_run-таблицу; в живой БД они не развёрнуты, а паттерн предыдущих загрузов (релиз 41 `cbr_api_dataservice`) — прямая вставка obs с новым release_id. Следую фактическому паттерну.
2. **metric_type='primary'** (CHECK-ограничение схемы: primary/derived/nowcast_model).
3. **Компоненты денежных агрегатов** — в `sub_dimension='component: <имя>'`, агрегат «Всего» — пустой sub_dimension (для М2 element 12 «Всего» = сам агрегат).
4. **Курсы**: у КЭП уже есть уровни USD/EUR (kep1_10x), поэтому из API взяты только индексы (nominal/NEER/real/REER × mom/dec-yoy/ytd), которые в v2 отсутствовали.
5. **SA-задолженность по ИЖК** (ds55/56) — новая метрика: `sszk` в БД относится к кредитам физлицам (pub20), не к ИЖК.
6. **Продление ИЖК**: sub_dimension='' (как у существующих строк релиза 2), assessment='final', status='raw'.

## Ограничения и следующий шаг

- Релизы 88–90 в статусе `loaded`, не `verified` — верификацию против независимого источника (пресс-релизы ЦБ) можно провести при следующем прогоне и поднять статус.
- `izhk_rate_rub`/`izhk_rate_fx` дублируют частично существующую `irz` (ставка ИЖК из VFS) — при разметке ядра выбрать один канонический код (рекомендация: `irz` с разбиением sub_dimension по валюте; новые коды пометить `merged`).
- Ночные обновления: скрипт идемпотентен (повторный запуск вставит только новые точки нового релиза); для cron-обновления достаточно перезапуска.

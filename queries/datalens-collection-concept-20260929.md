# Коллекция дашбордов DataLens «Мониторинг региона и округа» — концепция (2026-09-29)

Адресаты — три зала приёмки: сотрудники Отделений (регион), ГУ (федеральный округ),
Департамент ДКП (РФ). Один датасет, три витрины, единый словарь метрик. Блоки — те же,
что в срезе region_slice (A/B/C/E/F: цены, труд/спрос, ДКУ, жильё, опоры), плюс
инфраструктурный дашборд здоровья БД (уже спроектирован 28.09).

## Архитектура: трёхслойная

1. **Слой данных (1 датасет на тему, не на аудиторию)** — SQL поверх PG на ВМ
   (`research_wiki`, подключение через внутреннюю сеть YC или SSH-тоннель).
   Не плодим датасеты по регионам: один датасет + параметры на чарте.
2. **Слой чартов** — именованные чарты (таблица, линия, карта-choropleth, индикатор),
   переиспользуемые между дашбордами.
3. **Слой дашбордов** — дашборд = вкладки × аудитория; глобальные селекторы
   (регион, дата) на уровне дашборда, «привязкой к чартам».

## Состав коллекции (4 дашборда)

### Д1. «Паспорт региона» (адресат: Отделения, 85+ селектов)
Рабочая лошадка Отделений: один регион — вся картина. Дейли селектор региона.
- **Вкладка «Сводка»**: индикатор-строка (ИПЦ мес, ЗП, безработица, ввод жилья,
  ставка ИЖК), спарклайны 13 точек по каждой метрике, флаг свежести.
- **Вкладка «Кредитование»**: zkf, zyi, vhdt/vmd, vhlvt/oipflrrivrsrf, ставка ИЖК,
  просрочка ИЖК; YoY и MoM (SQL-окно).
- **Вкладка «Жильё»**: ввод всего/ИЖС помесячно, доля ИЖС, ИЖС-на фоне ФО.
- **Вкладка «Рейтинг в округе»**: позиция региона среди своих соседей по ФО —
  таблица с подсветкой ранга, 4 колонки (регион, значение, ранг, ФО).

### Д2. «Округ» (адресат: ГУ)
Фильтр-селектор ФО → внутри: карта субъектов (choropleth по выбранной метрике),
таблица лидеров/аутсайдеров, сопоставление с РФ.
- Карта по метрикам среза (смена метрики чартом-дисплеем).
- Топ/анти-топ по каждой метрике (с фильтром малых знаменателей,
  см. `queries/region-slice-anomaly-review-202610.md`: 3-мес Y/Y, не MoM).
- РФ-контекст: значение по стране (КЭП) против медианы ФО.

### Д3. «Россия» (адресат: ДДКП, 23.10.2026)
Разворот по федеральным округам: 8 строк (или 7 с НАО-агрегацией в одной),
метрики: ИПЦ, ввод жилья, кредиты физ/юр, ставка ИЖК, ВРП годовой.
Плюс федеральные ряды (КЭП): ИКВ, ВВП (с пометкой лага).
- **Вкладка «Пресс-слайд»**: 6-8 индикаторов, ровно тот состав, что идёт в sitrep СД.
- **Вкладка «Трансмиссия»**: ставка ИЖК по округам + выдачи + ввод —
  проверка H-021 (доля ИЖС против чувствительности к ставке) в один взгляд.
- **Вкладка «Регионы-аномалии»**: те же данные, что и в region_slice, но с
  автофильтром малых знаменателей (см. region-slice-anomaly).

### Д4. «Здоровье БД» (уже спроектирован 28.09, `datalens-db-health-dashboard-20260928.md`)
Инфраструктурный, виден только нам: свежесть 18 метрик, покрытие по источникам,
дыры в периодах, число наблюдений. Сюда же добавляется cron-алерт 04:00.

## Датасеты (4, SQL поверх PG)

| Датасет | SQL | Заточен |
|---|---|---|
| ds_region_monthly | region_slice как в region_slice_full.py (регион × метрика × месяц) | все 3 витрины |
| ds_region_rating | то же + оконная функция RANK() OVER (PARTITION BY parent_id) | Д1 рейтинги, Д2 топы |
| ds_rf_trend | РФ-агрегаты + КЭП (ИКВ, ВВП), ВРП | Д3 |
| db_health | существующий SQL из 28.09 дашборда | Д4 |

## Селекторы (на уровне дашборда, «привязка к чартам»)

- **Д1**: селектор региона (вирт-поле со списком 85 субъектов), период — «на дату»
  (последняя доступная автоматически, без выбора календаря — важно для Отделений,
  которые не хотят щёлкать дату).
- **Д2**: селектор ФО (8 значений), внутри округ — все метрики против медианы ФО.
- **Д3**: без селектора субъекта; селектор метрики + период.
- Все: флажок «показывать только свежие данные» (порог по дням из db_freshness_check).

## Ограничения и заметки

- **D и общероссийские условия не входят** — решение владельца (26.09): блок D
  (условия в строительстве) не в срезе, добавлять только по явной команде.
- **Наименование ФО**: canonical в `core.region` — 8 значений `federal_district`
  (id 2..9), parent_id=1; субъекты через parent → ФО join готов.
- **Флаг «Независимый расчет, не связанный с Банком России»** обязателен в футере
  каждого дашборда (решение 28.09).
- **Свежесть**: дашборд показывает последнюю точку ряда с пометкой «на дату» —
  не маскирует устаревание.
- Данные (вход через `region_slice`), не SQL-запрос в моменте: экспорт JSON-слой
  (см. `passport_regions_export.py`) — так чарты Д1/Д2 не бьют по PG на каждый
  рендер, PG нужен только для Д4 и Д3 (федеральные, малые выборки).

## Порядок реализации

1. Датасеты (4) поверх PG — сегодня (SQL готов из среза).
2. Д1 «Паспорт региона» — 2-3 чарта (сводка + кредитование) — первично для Отделений.
3. Д2 «Округ» — карта + рейтинг.
4. Д3 «Россия» — федеральные индикаторы к 08.10 (факт-блок СД).
5. Д4 — уже спроектирован, собрать из 28.09 спеки.

## Что понадобится от владельца

- Веб-консоль YC: создать воркспейс DataLens, подключение к PG через внутреннюю сеть
  (у ВМ уже есть сервисный аккаунт) — из CLI включение невозможно, только веб.
- Кто смотрит: если дашборды нужны только нам (без шаринга) — достаточно воркспейса;
  если Отделения/ГУ — решаем вопрос с доступами (DataLens имеет свою ACL).

## Проверяемые гипотезы из этого дашборда

- H-021 (доля ИЖС × чувствительность к ставке) — вкладка «Трансмиссия» Д3.
- H-020 (разброс ставок ИЖК вокруг средней) — Д1 «Кредитование»: std по регионам ФО.
- H-022 (юрлица опережают нежилую стройку) — Д2: корреляция zyi → nonres_annual.

# Спецификация датасета DataLens

Практическое руководство по созданию датасета, чартов и дашборда в DataLens
вручную (через интерфейс, под пользовательской лицензией). Составлено
18.09.2026 после исправления рубежа 5; опирается на витрину
`core.v_datalens_observations`.

## Почему вручную

Программный доступ через API DataLens (`api.datalens.tech`) требует, чтобы у
обращающегося субъекта было собственное рабочее место. У организации одно
бесплатное место, и оно занято владельцем; `LICENSE_IS_REQUIRED` возвращается
на все методы. Второе место — 990 ₽/мес, при двух местах платят за оба
(1 980 ₽/мес). Выбран бесплатный путь: датасет собирается в интерфейсе.

## Источник данных

Подключение уже настроено (см. `queries/datalens-connection.md`):

- **Хост** `89.169.168.214`, порт `5432`
- **База** `research_wiki` (подчёркивание, не дефис)
- **Пользователь** `datalens_ro`, права только на чтение
- **TLS** собственный удостоверяющий центр, `verify-full`, публичный
  сертификат `pg_ca.crt` (`data/certs/pg_ca.crt`)
- **Таблица для датасета** `core.v_datalens_observations` — представление,
  обновляется автоматически вслед за данными

Размер витрины: **2 112 964 строки**, период с января 1990 по август 2026.

### Показатель (Measure)

`value` — числовое значение наблюдения.

Вспомогательное `value_str` — текстовое представление (сейчас пусто во всех
строках, в датасет можно не брать).

## Обязательный фильтр

**`value NOT IN (−99 999 999, −77 777 777)`** — отсекаются только официальные
коды-заполнители Росстата. Разбор значений витрины:

```
NULL                                       676
заполнители (−99 999 999, −77 777 777)  27 217   ← только их и исключаем
нули                                   386 909   ← настоящие значения
отрицательные                            2 526   ← настоящие значения
положительные                        1 756 963
```

Заполнители — официальные коды Росстата: `−99999999` означает «нет
информации», `−77777777` — «скрыто». Если их не отсечь, средние и максимумы
уезжают в минус на порядки.

**Фильтр `value > 0` применять нельзя.** Он выбрасывает 389 435 строк
(18% данных), которые являются настоящими значениями:

- 386 909 нулей — ноль введённых метров за месяц, нулевая просроченная
  задолженность. У `okb` (выдачи ипотеки) 8 565 нулей из 25 920 — без них
  ряд рвётся.
- 2 526 отрицательных — убыток, отрицательная динамика, сальдо миграции.

Ещё одно следствие: метрика `obl` (уровень книги заявок, 82 строки) состоит
целиком из отрицательных значений, и под фильтром `value > 0` в датасет
вообще не попадала.

Исключение — расчёт логарифмов и средних геометрических: там нуль даёт
`NULL` и выпадает сам, отдельный фильтр не нужен.

## Разрез `sub_dimension`

Здесь лежит всё, что различает наблюдения внутри одной метрики, региона и
периода: рынок жилья (первичный/вторичный), валюта, вид ряда, продукт, состав
региона, номер листа ДОМ.РФ. Формат — пары через вертикальную черту:

```
валюта: RUB
ед.: Декабрь к декабрю предыдущего года, в процентах
product: Цемент (все гидравлические) | ед.: тыс.т | строка 1
ряд: stock | лист: 01_01_45 | строка 4473
состав: г. Москва | market: primary | ед.: руб
```

Замечания для работы в датасете:

- у 723 652 строк разрез пуст — это наблюдения без дополнительных разрезов,
  и это нормально;
- префиксы служебные, но читаемые; при построении чартов по конкретному
  разрезу удобно использовать `LIKE '%market: primary%'` — проверено, так
  отбирается 5 807 строк (первичный рынок жилья);
- хвост `строка N` встречается только там, где иначе ключ повторился (112
  строк в стройматериалах, 857 862 в ДОМ.РФ, где это нумерация строк листа).

Если датасет строится для конкретной темы, разрез можно не выносить в
измерение, а держать фильтром.

## Порядок создания в интерфейсе

**Шаг 1. Датасет.** В воркбуке → «Создать» → «Датасет» → выбрать подключение
`research_wiki` → перетащить таблицу `core.v_datalens_observations` в рабочую
область. DataLens предложит разложить поля: числовые в «Показатели»,
остальные в «Измерения». Агрегацию для `value` поставить **«Сумма»** только
если нужен суммарный объём, в остальных случаях — **«Среднее»** или вообще
без агрегации; для временных рядов предпочтительнее неагрегированное значение.

**Шаг 2. Фильтр.** На вкладке «Фильтры» датасета задать
`value NOT IN (-99999999, -77777777)`. Тогда он применится ко всем чартам на
этом датасете — удобнее, чем повторять в каждом. Именно это условие, а не
`value > 0`: второе выбросит 18% настоящих данных.

**Шаг 3. Вычисляемое поле** (необязательно, но полезно). Если нужен единый
столбец периода для оси времени:

```
DATETIME(STR(INT([year])) + '-01-01')
```

Для месячных рядов лучше брать готовый `period_start` — он уже дата.

**Шаг 4. Чарты.** Первые три, которые покажут картину:

- **Линейный график**: ось X — `period_start`, ось Y — `value` (среднее),
  в цвет — `region_name`; фильтры: `metric_code = tkzk`,
  `region_level = 'region'`. Это динамика цены квадратного метра по регионам.
- **Столбчатая диаграмма**: ось X — `year`, Y — `value` (сумма), фильтры:
  `metric_code = kko`, `source_code = 'cbr'`. Это количество выданных
  кредитов по годам.
- **Карта (полигональная)**: геоточка — `region_code`, цвет — `value`
  (среднее), фильтр: `metric_code = snz`, последний доступный год. Проверка
  региональной дифференциации.

**Шаг 5. Дашборд.** Собрать чарты на одной странице, добавить селекторы:
`metric_name` (поиск по названию), `source_name`, `year`.

## Что нужно проверить перед публикацией

- в названии чарта указывать метрику и период, иначе через месяц не
  вспомнить, что на графике;
- для `metric_code = usg_4` (уровень строительной готовности) в данных
  единственный регион — это не ошибка витрины, а свойство источника;
- если чарт строится по `sub_dimension`, проверить, что разрез не пустой,
  иначе выборка будет шире ожидаемой;
- при работе с ЦБ помнить: у одного показателя может быть несколько
  релизов (`release_label`), и без различения релиза значение задвоится.
  Фильтр по конкретному релизу снимает вопрос. Распределение публикаций
  по источникам: Росстат 33, Банк России 3, ДОМ.РФ 1, Росреестр 1 —
  у Росстата релизами различаются издания сборников и первичные выпуски
  (например, сборник `info-stat-06-2026/10-05` против бюллетеня ЦБ
  `cbr_bulletin_74` внутри строк Росстата).

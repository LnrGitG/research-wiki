# Словарь БД v2: поля и метрики короткими русскими формулировками

**Назначение:** чтобы при чтении отчётов и протоколов сразу улавливать логику.
Справочник к спеке queries/db-v2-reload-spec.md и протоколу M0.

---

## 1. Таблицы-справочники (кто, где, чем, как часто)

### source — организации-источники
- **source_code** — короткое латинское имя источника: rosstat, cbr, domrf, minfin, fnso, yandex, eiszs, nostroy.
- **name_ru** — полное название («Банк России»).
- **access_method** — как достаём данные: api (сеть), scrape (парсинг сайта), file (скачивание файлов), manual (руками).

### dataset — конкретный продукт источника
Это «что качаем»: не организация, а именно файл/выгрузка/раздел.
- **dataset_code** — код продукта, например vfs-0420218 (форма ЦБ по закладным), domrf-price-index, kep-1 (КЭП Росстата).
- **release_url** — где лежит на источнике.
- **schedule** — регламент публикации, «monthly+14d» = раз в месяц, через 14 дней после отчётного периода.
- **is_active** — живой продукт или закрытый.

### region — территория измерения
- **region_code** — канонический код (ОКАТО/ОКТМО).
- **level** — уровень: rf (страна), federal_district (ФО), region (субъект).
- **parent_id** — кто включает этот регион (область → округ).
- **oktmo, okato, iso_code** — официальные кодовые соответствия.
- **valid_from / valid_to** — период действия имени (учёт переименований и укрупнения регионов: старые записи не удаляются, закрываются датой).

### unit — единица измерения
- **unit_code** — канонический код: mln_rub (млн руб.), rub_m2 (руб/м²), count (штук), pct (процент), index_100 (индекс, база 100), thou_m2 (тыс. м²).
- **dim** — физическая природа: money (деньги), area (площадь), count (количество), ratio (отношение), index (индекс), time (время). Нужна, чтобы не сравнивать «деньги» с «площадью» при автоматических проверках.

### frequency — частота ряда
- **freq_code** — W (неделя), M (месяц), Q (квартал), A (год).
- **periods_per_year** — точек в году (12, 4, 1) — для проверок свежести и сшивки.

## 2. Каталог показателей (что измеряем)

### domain — тематический раздел
- **domain_code** — supply (предложение: ввод, СМР), prices (цены), transactions (сделки), credit (кредитование), developers (застройщики), budget (бюджет и субсидии), search_leads (поисковые лиды Wordstat), macro_input (макровходы: ставка, ИПЦ, доходы), demography (демография).
- **parent_id** — вложенные домены (если понадобится).

### metric — показатель (главная таблица каталога)
- **metric_code** — уникальный код: smr_full_m (СМР РФ, месяц), ikv_rf_q (ИКВ РФ, квартал), cbr_izhk_rate_m (ставка ИЖК, месяц).
- **name_ru / name_en** — русское и английское названия.
- **definition_ru** — методология источника своими словами (что именно считают).
- **domain_id** — тематический раздел.
- **parent_metric_id** — подчинённость: у «ввода ИЖС» родитель «ввод жилья всего». Логика владельца «нам важнее агрегаты» закреплена прямо в каталоге.
- **relation_type** — тип связи с родителем: is_part_of (часть целого), derived_from (вычислен из), complement (дополнение).
- **unit_id, frequency_id** — каноническая единица и частота.
- **is_aggregate** — это агрегат (РФ/ФО = сумма субъектов). Защита от ловушек типа «region_id=1 со страной в поле».
- **priority** — core (ядро, в витрине моделирования), extended (важный, не в базовой витрине), context (справочный). Всё вне core — кандидаты на исключение.

### metric_dataset_map — откуда метрика берётся
- **native_code** — код показателя у источника (например id ЕМИСС).
- **native_unit** — единица в оригинале (если отличается от канона).
- **scale_factor** — множитель пересчёта (тыс. руб. → млн руб. = 0,001). Загрузка сразу приводит к канону, анализ не думает о масштабах.

## 3. Конвейер загрузки (аудит и верификация)

### load_run — один запуск загрузки = одна «версия» данных
- **run_id** — номер версии. Все данные этой загрузки помечены этим номером; откат = смена активной версии.
- **file_sha256** — отпечаток исходного файла (тот же файл → та же загрузка не повторится).
- **source_published_at** — дата публикации на источнике (не дата в файле!) — для расчёта лагов «событие → данные».
- **parser_version** — git-версия парсера: какой код получил эти данные.
- **status** — ok (всё проверено), partial (частично, в витрину не попадает), failed, verified (прошёл ручную верификацию).
- **rows_parsed / inserted / rejected** — сколько прочитано / записано / отброшено. Rejected = качество карточки источника.

### load_check — верификация каждого файла
- **check_kind** — тип проверки: spot_value (сверка ячеек с эталоном), row_count (счётчик строк), hash_series (сверка ряда целиком), region_count (сколько регионов).
- **check_detail** — что ждали и что получили (JSON).
- **passed** — пройдена ли. Пока не все проверки пройдены — данные не «текущие».

## 4. Данные (сама таблица значений)

### observation — одно значение одного показателя
- **metric_id + region_id + frequency_id + period_start** — четыре ключа измерения: что / где / как часто / когда. period_end — конец периода (для квартала/года).
- **value** — значение в канонической единице (с ним работают все).
- **value_native** — значение как в источнике (для аудита пересчёта).
- **run_id** — какой загрузкой получено. **Версионность: ревизия = новая строка, а не перезапись.**
- **is_current** — активная версия (последняя проверенная загрузка). Витрина показывает только их.
- **quality_flags** — метки качества строки: outlier (выброс), revision (значение пересчитано источником), imputed (вставлен пропуск), break (разрыв методологии), provisional (предварительные данные).

### series_revision — история ревизий
- **prev_run_id / prev_value → new_run_id / new_value** — что было и что стало при новой загрузке.
- **abs_change / pct_change** — размер пересчёта. Автодетект: источник задним числом изменил историю — мы это видим и фиксируем, не теряем.

### freshness — актуальность (пересчёт по расписанию)
- **last_obs_at** — дата последней точки.
- **obs_count** — глубина ряда.
- **freshness** — fresh (в пределах регламента), lagging (запаздывает), stale (мертв).
- **expected_next** — когда ждем следующую точку по регламенту. Отклонение = сигнал проверить источник.

## 5. Витрины (что читать отчётам)

- **v_core_panel** — готовая панель для моделирования: только core-метрики, только актуальные значения. Сюда смотрят спеки, bridge, MIDAS.
- **v_freshness_board** — дашборд актуальности: что устарело, кого ждать.

## 6. Промежуточный слой (решено добавить в M1)

- **v2_stage.stg_rows** — сырой приёмник парсеров: парсер пишет сюда и никуда больше.
- **v2_stage.stg_resolve** — результат сопоставления со справочниками; reject'и копятся как измеримое качество.
- **v2_stage.stg_verify** — спот-чеки до вставки в основную таблицу.

## 7. Логика одного отчёта (сквозной пример)

«Ставка ИЖК в Белгородской области, июль 2026, свежая?»:
metric_code=cbr_izhk_rate_m (домен credit, приоритет core) → region=Белгородская
→ period_start=2026-07-01 → value=11,1 (pct, value_native=11,1) → run_id=N
(загрузка от 21.09, файл sha256=…, опубликован источником 12.09, лаг 9 дней)
→ is_current=TRUE, quality_flags=[] (без меток) → freshness=fresh (ожидание
следующей точки ~ середина следующего месяца по регламенту monthly+14d).

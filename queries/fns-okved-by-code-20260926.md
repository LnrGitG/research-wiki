# ФНС 1-НОМ: выравнивание по кодам ОКВЭД вместо позиций колонок (26.09.2026)

Задача: сделать ряд 2018–2026 сопоставимым. Разбивка ОКВЭД в выгрузках 1-НОМ менялась
(89 колонок в 2020, 105 в 2024, 91 в 2025–2026), поэтому позиционная привязка метрик делала
сквозное сопоставление некорректным. Инструмент: `scripts/fix_fns_okved_codes.py`,
релиз **113** `fns_1nom_okved_by_code_2018-2026`.

## 1. Источник меток — пер-винтажные справочники

Для каждого винтажа скачан его собственный справочник полей
`https://data.nalog.ru/opendata/7707329152-1nom/structure-ГГГГММДД.csv` (кэш в `raw/fns/structure/`).
Найдено три формата справочника, все разобраны одним парсером (поиск ячейки вида `G<номер>`
и следующего за ней текстового описания):

- современный (2025–2026) — четыре колонки: `field name | english | russian | format`;
- 2024 — одна колонка с разделителем `;`, поле на 4-й позиции;
- 2018–2020 — одна колонка, поле на 4-й позиции, описание без слова «ОКВЭД».

Из описания извлекается канонический ключ: `«Код по ОКВЭД F 41-43 строительство»` → `F4143`,
`«Код по ОКВЭД А 01-03 …»` → `A0103`; строки без кода ОКВЭД получают текстовые ключи
(`NOTDIST` для «суммы, не распределённые по ОКВЭД», `INDIVIDUALS`, `OTHER_ACTIVITY`).
Старые метки без кода (2018–2020) сопоставляются с современными по нормализованному тексту описания.

## 2. Результат

Релиз **113** `fns_1nom_okved_by_code_2018-2026`: **436 882 точки**, 85 регионов, **110 канонических
ключей ОКВЭД**, период **2018-01-01 … 2026-04-01**. Крупные ключи покрывают 51 винтаж из 52 —
единственный пропуск `1nom_20241216.csv` (промежуточная выгрузка середины декабря, для неё
справочника `structure-20241216.csv` на портале нет).

Позиционные метрики `fns_1nom_okved_<номер>` (105 штук, релиз 112) переведены в `deprecated`
с пометкой о причине; данные в них сохранены. Побочно вычищены 412 пустых метрик-заглушек
`fns_1nom_key_SLUG_*` — ключи, распознанные по англоязычному описанию на промежуточной итерации
парсера, без значений.

## 3. Проверка

**Сверка с позиционной загрузкой.** Для винтажа 2026-01-01 по трём регионам (Москва, Краснодарский
край, Свердловская область) сравнены значения позиционных и ключевых метрик: **267 совпадений,
0 расхождений, 0 отсутствующих ключей**. То есть там, где позиционная привязка была верна (современные
винтажи), ключевая загрузка воспроизводит её в точности.

**Непрерывность ряда.** Ключ `L68` (операции с недвижимым имуществом), Москва, начисления страховых
взносов на ОСС по годовым снапшотам (01.01), тыс. руб:

| Год | Значение |
|---|---|
| 2018-01-01 | 43 255 280 |
| 2020-01-01 | 54 381 140 |
| 2022-01-01 | 58 631 796 |
| 2024-01-01 | 80 010 954 |
| 2025-01-01 | 78 092 286 |
| 2026-01-01 | 96 215 059 |

Итого рост за восемь лет в 2,2 раза с просадкой в 2025 году — ряд непрерывный, без разрывов на
стыках винтажей, что и было целью выравнивания.

**Семантика периодов.** Снапшоты 01.01 — итог предыдущего года, 01.04 / 01.07 / 01.10 —
нарастающий итог соответствующего квартала (проверено на `L68`: 2026-01-01 = 96,2 млрд за 2025 год,
2026-04-01 = 25,5 млрд за I квартал 2026). В базе это отражено частотой: 3 (годовая) для 01.01,
6 (квартальная) для остальных.

## 4. Как пользоваться

```
-- сквозной ряд по отрасли: ключ ОКВЭД в коде метрики
SELECT o.period_start, r.name_ru, o.value
FROM core.observation_v2 o
JOIN core.metric m USING (metric_id)
JOIN core.region r USING (region_id)
WHERE m.metric_code = 'fns_1nom_key_L68'          -- операции с недвижимостью
  AND r.name_ru = 'Москва' AND o.observation_status <> 'rejected'
ORDER BY o.period_start;
```

Ключи строительного блока: `F41`, `F42`, `F43` (строительство), `L68` (операции с недвижимостью),
`C1033`-группа (обрабатывающие производства, включая стройматериалы), плюс `NOTDIST` и `INDIVIDUALS`.

Пометка: независимый технический документ, не связан с Банком России.

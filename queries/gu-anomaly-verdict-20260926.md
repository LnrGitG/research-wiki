# Вердикт по аудиту скрина аномалий среза v2 (26.09.2026)

Разбор двух независимых прогонов: скрин аномалий (делегат `deleg_2130201d`) и слепой аудит
(делегат `deleg_2b748acf`). Ниже — что подтвердилось, где прогоны разошлись и что это значит для
факт-блока к 08.10.

## 1. Артефакт скрина верен

Пересчёт родителем совпал с артефактом до сотых: в источнике 4 960 пар «предыдущее → текущее»,
после фильтра малых знаменателей (порог 10 % медианы предыдущего значения по метрике) остаётся
**4 696** — ровно столько строк в `data/gu-anomaly-screen-202610.csv`. Аудитор независимо пересчитал
темпы по 3 680 строкам (все метрики, кроме `emiss_31074_cpi_prevm_m` и `virtr`) — расхождений
больше 0,01 п.п. нет; на случайной выборке 200 строк (seed 42) и на всех строках `vmd` и `zyli`
расхождений по `value`/`value_prev` тоже нет.

**Самоотчёт первого делегата артефакту не соответствует.** В текстовой сводке он привёл
Свердловскую как 2,1 → 3,8 (+80,95 %), Тамбовскую как 0,12 → 7,23, Чукотку как 0,05 → 0,099
(+98 %). Ни одной такой пары в данных нет: фактические значения — 1,5 → 2,7; 68 → 3 957;
20 210 → 20 520. Файл корректен, проза — нет. Правило «проверять артефакт, а не отчёт»
подтвердилось на первом же реальном прогоне.

## 3. Где прогоны разошлись и как это разрешено

Аудитор в разделе «совпадающие ряды метрик» нашёл только одну пару — `rosstat_housing_pop_m` против
`rosstat_housing_total_m` (1 регион) и **пропустил дубликат `zkf`/`vmd`**. Причина расхождения
критериев: аудитор требовал совпадения рядов на **одинаковом наборе периодов**, а у `zkf` и `vmd`
периоды сдвинуты на месяц (`zkf` — февраль…август, `vmd` — январь…июль). По общим периодам значения
совпадают полностью.

Проверено по сырому тексту файла, без обработки:

```
vmd,Тамбовская область,5,2026-02-01,150749
zkf,Тамбовская область,5,2026-02-01,150749
vmd,Москва,5,2026-02-01,4450559
zkf,Москва,5,2026-02-01,4450559
```

Совпадение — по всем 85 регионам на общих периодах.

## 4. Дефект данных, найденный в базе (важнее самих аномалий)

`zkf` («Задолженность по кредитам физлицам», metric_id 190) и `vmd` (`vfs_mortgage_debt`,
metric_id 769) несут **один и тот же ряд** — на федеральном уровне 36 589 548 млн руб за май 2026
в обоих, и так по каждому месяцу. Который из них неверен, показывает сверка семейства:

| Метрика | Название | РФ, май 2026, млн руб |
|---|---|---|
| `zkf` | Задолженность по кредитам физлицам | 36 589 548 |
| `zkfi_2` | то же (итого) | 36 589 548 |
| `zkfr` | то же (в рублях) | 36 577 219 |
| `zkfp` | то же (в т.ч. просроченная) | 1 657 422 |
| `zia` | **Задолженность по ИЖК** | **22 171 365** |
| `vmd` | `vfs_mortgage_debt` | 36 589 548 ← дубликат |

Семейство `zkf` внутренне согласовано (рублёвая часть плюс валютная дают итог, просроченная
существенно меньше), а истинная задолженность по ИЖК — 22,2 трлн руб (`zia`). Следовательно,
**`vmd` загружен не той серией**: он получил общий портфель кредитов физлицам вместо ипотечного.
Практическое следствие — в срезе для докладов ГУ столбец «Задолженность по ИЖК» завышен
в 1,65 раза (36,6 против 22,2 трлн), а столбец «кредиты физлицам» фактически дублируется.

Дополнительно: `zyli` в базе описана как «Задолженность юридических лиц (в инвалюте)» (7 410 161 млн
руб на май 2026), тогда как итоговый корпоративный долг — `zyli_2` / `zyi` (85 289 107 млн).
В записке среза `zyli` подана как «кредиты юрлиц», что неверно: это только валютная часть.
Плюс 23 региона имеют полностью нулевой ряд по `zyli` — ожидаемо для валютной компоненты, но
исключает метрику из межрегиональных сравнений без оговорки.

Нулевые ставки ИЖК (`virtr = 0`: Чукотский АО — два месяца, Ненецкий АО, Республика Ингушетия)
трактовать как значение ставки нельзя: это отсутствие выдач, тот же паттерн, что в `izhk_rate_fx`.

## 5. Что делать (предложение)

1. Переинжестить `vmd` (`vfs_mortgage_debt`) из корректной серии задолженности по ИЖК (`zia` либо
   поле `vfs_*` того же релиза) — до факт-блока 08.10, иначе региональный срез уйдёт в доклады ГУ
   с завышенной ипотечной задолженностью.
2. Поправить записку среза: описание `zyli` (валютная часть, а не корпоративный кредит в целом),
   пометка о нулевых `virtr`, снятие цифры «+99,5 % по Чукотке».
3. Ужесточить критерий аудита: сверять ряды по **общим** периодам, а не по совпадению множеств
   периодов — иначе сдвинутые на месяц дубликаты не ловятся.
4. Регулярный контроль дублей: SQL-проверка «для каждой пары метрик одной частоты доля совпадающих
   значений на общих периодах» — раз в месяц, вместе с аудитом делегирования.

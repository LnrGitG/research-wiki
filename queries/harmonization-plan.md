# Гармонизация данных: staging → core

Данные перенесены в PostgreSQL точным слепком исходников (схема `staging`).
Гармонизация превращает их в целевую модель: наблюдения с устойчивыми
идентификаторами показателей, регионов и версий оценок.

## Объём

| Источник | Строк | Показателей |
|---|---|---|
| Росстат, `observations` | 42 517 | 35 |
| ДОМ.РФ, `domrf_indicators` | 857 862 | 126 |
| ЦБ, три таблицы | 311 721 | 98 |
| `panel` (регионы) | 308 952 | 201 |
| ФНС, `firms_f` | 3 715 553 | (firm-level, отложено) |
| МСФО девелоперов | 512 | 11 |
| Росреестр, сделки и ИКВ | ~8 300 | 4 |

Фирменные данные ФНС (3.7 млн строк) при гармонизации не разбираются
по показателям — это сырьё для секторных агрегатов.

## Рубежи

### Рубеж 1. Справочники — ВЫПОЛНЕНО 17.09.2026

Заполнены `core.source`, `core.unit`, `core.frequency`:
шесть источников (Росстат, ЦБ, ДОМ.РФ, Росреестр, ФНС, Smart-Lab
с уровнем надёжности `official` для государственных), 20 единиц
измерения, четыре частоты.

Ограничения схемы учтены: `period_type` только из пяти значений,
`months_per_period` в диапазоне 1–12 (для дневной и недельной частоты
используется тип `date`), `reliability` из фиксированного набора.

### Рубеж 2. Метрики — ВЫПОЛНЕНО 17.09.2026

Записано **483 метрики** в `core.metric`, все с кодом, единицей и частотой.

Правило кодирования (согласовано с владельцем): если в источнике есть
готовый код — используется он (например `y477030001` из `panel`);
иначе код строится из первых букв слов названия после транслитерации
(«Площадь квартир в жилых зданиях» → `pkzznns`).

Проверка целостности: уникальных кодов 483 из 483, дублей нет,
все коды соответствуют шаблону `[a-z0-9_]+`, длиннее 20 символов — ни одного,
без единицы или частоты — ни одной записи.

**Обнаруженные дефекты исходных данных:**

1. В справочнике `indicators` поле `unit` часто содержит не единицу,
   а скобочную пометку или продолжение названия — артефакт парсинга
   листов Excel. Единица извлекается разбором текста в скобках
   (`unit_parser.py`), а при отсутствии — выводом по смысловым правилам
   («Количество …» → `units`, «Доля …» → `pct`).
2. Две записи справочника имеют число вместо названия (`id=35` — «1»,
   `id=48` — «9»): у первой имя потеряно, у второй название сместилось
   в поле `unit`. Обе обработаны.

### Рубеж 3. Наблюдения — ВЫПОЛНЕНО 17.09.2026

Перенос строк `staging` в `core.observation` с вычислением ключа
`(metric_id, region_id, frequency_id, period_start, source_id, release_id,
assessment_type, sub_dimension)`.

Особенности:
- дубли ЦБ (`cbr_mortgage_monthly` есть и в `rosstat_construction`,
  и в `cbr_lending`) — разные релизы одного показателя, а не два показателя;
- составные подписи Росреестра расщепить на три колонки;
- варианты «с АО» и «без АО» — разные регионы (`arkhangelsk_nao` / `arkhangelsk`).

#### 3б. Перенос наблюдений

Скрипт `harmonize_3b_observations.py` переносит строки в `core.observation`:
регион определяется по алиасам, нерегиональные подписи → `sub_dimension`,
период разбирается в `period_start`/`period_end`, версия оценки —
`preliminary` для текущего года и `final` для закрытых периодов.

**Найденный и исправленный баг.** Ключ показателя нормализовался (убирались
сноски вида «1)»), а словарь метрик строился по сырому названию — из-за
рассогласования **13 103 строки** не находили свою метрику. После исправления
без метрики остаются 1 112 строк — две записи справочника `indicators`
с числовыми названиями (`id=35` — «1», `id=48` — «9»).


**Итог переноса: 551 022 наблюдения.** Периоды охватывают 1990-01-01 … 2026-08-31.

| Источник | Частота | Наблюдений |
|---|---|---|
| ЦБ | месячная | 303 978 |
| Росстат | годовая | 232 060 |
| Росстат | месячная | 6 764 |
| ДОМ.РФ | месячная | 5 025 |
| Росстат | квартальная | 2 350 |

Версии оценки: 494 429 окончательных (`final`) и 56 588 предварительных

Подразрезы: `категория` (2 572 — виды производственных мощностей, типы зданий),
`вид работ` (80), `год` (24). Это измерения внутри показателя, а не территории.

**Целостность:** ноль NULL и ноль битых ссылок по всем пяти внешним ключам
(`region_id`, `metric_id`, `source_id`, `release_id`, `frequency_id`).
Пустых значений — 670 из 551 022.

#### Препятствия, устранённые на этом рубеже

1. **Память VDS.** На VDS 961 МБ, свободно было 245 МБ; загрузка `panel`
   (309 тыс. строк) целиком убивала процесс по OOM (код 137). Перенос
   переведён на потоковое чтение серверным курсором **и выполнен на самой ВМ**
   (8 ГБ, база локальная) — это сняло и проблему памяти, и зависимость от туннеля.

2. **Коммит уничтожал серверный курсор.** `ON CONFLICT` с порционными коммитами
   внутри цикла давал `InvalidCursorName: cursor does not exist` — серверный
   курсор живёт в транзакции, а коммит её завершает. Чтение и запись разведены
   на **разные соединения**.

3. **Баг сопоставления метрик.** Ключ нормализовался (снимались сноски «1)»),
   а словарь строился по сырому названию — терялось 13 103 строки. Обе стороны
   нормализуются одинаково.

4. **Гомоглифы.** Подписи вида «Российская Федеpация» и «Число кваpтиp»
   содержат латинские `p` внутри русских слов — добавлено снятие гомоглифов
   перед сопоставлением.

5. **Туннель к PostgreSQL** переведён в systemd-юнит `pg-tunnel.service`:
   фоновый `ssh -f -N` умирал при перезапуске шлюза и рвал многочасовую вставку.

## Инструменты

- `scripts/metric_codes.py` — генерация кодов (транслитерация, первые буквы, разрешение коллизий);
- `scripts/unit_parser.py` — определение единиц из текста и по смыслу;
- `scripts/harmonize_1_references.py` — справочники;
- `scripts/harmonize_2_metrics.py` — метрики (идемпотентный, есть `--dry-run`).

# Удаление legacy-таблицы core.observation

Разбор 18.09.2026. Таблица `core.observation` (рубеж 3 гармонизации,
551 022 строки) выведена из эксплуатации после проверки, что все её данные
сохранены в целевой `core.observation_v2`.

## Зачем это было нужно

Таблица жила параллельно с целевой и мешала:

- **блокировала чистку метрик** — внешний ключ `observation_metric_id_fkey`
  не давал удалить осиротевшие метрики;
- **путала при запросах** — легко было взять не ту таблицу: имена
  `observation` и `observation_v2` слишком похожи;
- **держала 551 022 строки**, из которых уникальными оказались ноль
  (см. ниже), ради примерно тысячи наблюдений, которых на деле тоже не было.

## Проверка перед удалением

Ключевой вопрос: есть ли в legacy данные, которых нет в целевой. Проверка
шла в несколько итераций, потому что наивные сравнения давали ложные сигналы.

**Ловушка первая — сравнение по неполному ключу.** Первый запрос сверял
`(метрика, регион, период)` и показал 8 139 строк «без пары». Но это ложная
тревога: при гармонизации метрики переназначались, и одни и те же данные
могли оказаться под другим `metric_id`.

**Ловушка вторая — NULL в сравнении значений.** Следующий запрос сравнивал
`o.value = v.value`, и при `NULL` результат всегда `NULL`, то есть «не
совпало». Правильно — `IS NOT DISTINCT FROM`. С ним картина изменилась:
30 909 строк вместо 31 559.

**Ловушка третья — метрики, «существующие только в legacy».** Их оказалось
две: `itzdrrm` (5 025 строк) и `vdpzdcn` (2 062). Но сверка с целевыми
двойниками показала:

```
itzdrrm (legacy, 5 025)  ↔  itzdr   (целевая, 5 025) — совпало 5 025
vdpzdcn (legacy, 2 062)  ↔  vdpzdcn_2 (целевая, 2 084) — совпало 2 062
```

То есть данные есть, просто под другими кодами.

**Ловушка четвёртая — путаница метрик с одинаковыми названиями.** У трёх
метрик с названием `debt` (id 167, 232, 247 — это долг по ипотеке, эскроу
и корпоративный) в legacy строки были привязаны не к тем идентификаторам,
что в целевой. Аналогично у пары `zylpi`/`zylpi_2` значения в legacy и
целевой оказались **перекрёстно перепутаны**. Это как раз следствие
переназначения метрик при гармонизации.

**Итоговый тест.** Строгий запрос без учёта `metric_id` — есть ли хотя бы
одна legacy-строка, чьё значение (по региону и периоду) отсутствует в
целевой вообще:

```
строк legacy без ЛЮБОГО двойника в v2: 0
```

Перекрёстные проверки подтвердили: `zylpi` 7 740 из 7 740, `zylpi_2`
7 740 из 7 740, `deb_3` 7 902 из 7 902, `deb` 7 902 из 7 902 — все имеют
двойника. **Ни одно значение не теряется.**

## Что мешало удалить

Помимо ключа на `core.metric` обнаружилась вторая зависимость, о которой
не знали: `note_obs_id_fkey` из таблицы `core.note` (аннотации к
наблюдениям). Таблица пуста (0 строк), но внешний ключ не давал сделать
`DROP`.

Решение: снять **только внешний ключ**, а таблицу `core.note` сохранить —
она часть схемы, и удалять её через `CASCADE` было бы неверно.

```
ALTER TABLE core.note DROP CONSTRAINT IF EXISTS note_obs_id_fkey;
DROP TABLE core.observation;
```

## Отдельная тонкость: владелец таблицы

`core.observation` принадлежала пользователю `postgres`, а рабочий
пользователь — `wiki` (не суперпользователь). Удаление выполнялось под
`sudo -u postgres`. Остальные таблицы `core` тоже принадлежат `postgres`,
кроме `observation_v2` и `observation_v2_old` — они на `wiki`.

## Точка возврата

- git-тег `backup/before-drop-legacy-20260918`
- дамп `legacy_observation.dump` (5,1 МБ) на ВМ и в бакете
  `wiki-research/backups/`
- схема обновлена: `db/schema/schema-live.sql` (1 330 строк, 20 таблиц)

Восстановить таблицу при необходимости:

```bash
pg_restore -h localhost -U wiki -d research_wiki legacy_observation.dump
```

## Что это меняет

Метрик стало 1 365 — ушли две пустые (`vdpzdcn`, `itzdrrm`), чьи данные
доступны под кодами `vdpzdcn_2` и `itzdr`. Если при построении чартов
понадобится «ввод жилья на 1000 человек» или «индекс цен ДОМ.РФ по
регионам», брать нужно именно эти коды.

Схема базы теперь однозначна: единственная таблица наблюдений —
`observation_v2`, единственное представление —
`v_datalens_observations`. Двусмысленности с именами больше нет.

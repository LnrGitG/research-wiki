# Карточки метрик v2 и векторный поиск по рядам (27.09.2026)

Задача: сделать 5,45 млн наблюдений и 3 945 метрик адресуемыми. До сегодняшнего дня ряд
находился только по коду, а слой `derived.metric_semantic` (1 821 запись) остался от v1 и
пересечения с v2-кодами не имел.

## Что построено

**Таблица `derived.metric_card`** — 3 530 карточек (все метрики, у которых есть хотя бы одно
неотклонённое наблюдение). Поля: код, название, описание, единица и частота на человеческом
языке, источники, тематические метки, уровень (региональный/федеральный), число наблюдений,
число регионов, границы периода, свежесть в днях, статус, текстовое описание `search_text`
и вектор `embedding vector(256)`.

**Векторы.** Яндекс `text-search-doc`, 256 измерений — та же модель, что для базы знаний
(`kb.chunk`, 33 346 чанков), поэтому масштаб и качество сопоставимы. Покрытие — **3 530 из 3 530,
сбоев ноль**. Вложения кэшируются по хешу текста (`data/etl/metric-card-embed-cache.json`),
повторный прогон обходит API для неизменившихся карточек: первый холодный прогон занял 20 минут,
повторный после правки тематических правил — 6 минут.

**Тематические метки** — правила по ключевым фрагментам названия, описания, кода и источника,
13 тем. Распределение: промышленность 593, жильё и строительство 571, кредит и денежная
политика 380, налоги и бюджет 346, население и демография 243, внешний сектор 205,
корпоративный сектор 132, ипотека 107, региональная экономика 105, труд и занятость 98,
цены и инфляция 80, потребительский спрос 78, уровень жизни. Плюс метки источника
(emiss, operational, housing, fns).

## Инструменты

```
python3 scripts/build_metric_cards.py              # пересборка карточек и векторов (кэш)
python3 scripts/build_metric_cards.py --skip-embed # без обращения к API
python3 scripts/metric_search.py "ипотечная задолженность по регионам" --limit 8
python3 scripts/metric_search.py "ввод жилья" --theme "жильё и строительство" --level региональный
python3 scripts/metric_search.py "задолженность по ИЖК" --with-values   # с последними значениями
python3 scripts/metric_search.py "1ном" --sql-only                      # без вектора, по подстроке
```

Запросы вкладываются моделью `text-search-query` (отдельная от doc-модели — так устроен Яндекс
Embeddings), поиск — косинусный по `embedding <=>`, фильтры по темам, уровню и источнику.

## Проверка качества поиска

| Запрос | Первые попадания |
|---|---|
| ипотечная задолженность по регионам | ИЖК в рублях (Росстат, 96 регионов), новые ипотечные кредиты физлицам (`nikfr`), доля ИЖК в кредитах физлиц (`dziszkpflrrivodr`) |
| ставка по ипотечным кредитам | `nikfr`, `sit` (ставка по ИЖК), `nikfi` |
| страховые взносы по отраслям экономики | ряд страховых взносов, затем `fns_1nom_key_C13` (производство текстильных изделий) |
| сколько квартир построили | количество квартир в проектных декларациях ЕИСЖС (`01_02_40`, `01_02_20`) |
| число вакансий и напряжённость рынка труда | `emp`, нагрузка незанятого населения на 100 заявленных вакансий КЭП 4.1.8 |

Фильтры проверены отдельно: тема «ипотека» + региональный уровень отдаёт только региональные
ипотечные ряды, тема «налоги и бюджет» — 346 карточек, подсветка последних значений показывает
регион.

## Ограничения, которые честно стоит знать

**Названия из источника переносятся как есть.** Ряды Росстата из КЭП и ЕМИСС часто называются
служебно («employment», «T_31: Доля задолженности по ИЖК … в разрезе субъектов»), поэтому
семантический поиск по ним работает хуже, чем по рядам ЦБ с человеческими названиями.
Лечится нормализацией названий — это следующая итерация, и она дёшева: `search_text`
пересобирается без обращения к внешнему API, если не менять текст (кэш по хешу).

**Свежесть — не гарантия качества.** В карточке есть `freshness_days`; верхние попадания
могут оказаться старым годовым рядом (например, ИЖК Росстата с последней точкой 2025-01-01),
хотя у нас есть свежий канонический `vmd` за июль 2026. Ранжирование чисто векторное, поэтому
при выборе ряда нужно смотреть на `period_max` в карточке.

**Дубли не разрешены.** Один и тот же показатель из разных источников (ИЖК ЦБ против жилищных
кредитов VFS, зарплата ЕМИСС против `snz`) остаётся разными карточками. Слой
`derived.metric_crosswalk` (223 записи) закрывает это лишь частично; доводить кросс-уок — отдельная
задача.

Пометка: независимый технический документ, не связан с Банком России.

## Дополнение (28.09.2026): ранжирование по свежести и частота продуктовых рядов

**Синонимы помогли не полностью.** Подстановка «Промпродукция, месяц: X» → «Производство продукции
(выпуск) за месяц: X» добавлена в поисковый текст и работает: узкий запрос «производство
портландцемента за месяц» сразу поднимает августовские ряды `pmpmd` и `pmpbmd` с единицами
(тыс. тонн). Но запрос «производство цемента и бетона» по-прежнему выводил наверх ряды 2023 года:
у них название буквально совпадает с запросом, и векторное сходство перебивает свежесть. Значит,
дело не в названиях, а в отсутствии учёта свежести при ранжировании.

**Что добавлено в поиск.** Флаг `--prefer-fresh` штрафует устаревшие ряды: к косинусному расстоянию
прибавляется до 0,06 за устаревание (линейно от нуля до 3650 дней). Флаг `--max-age-days N` жёстко
отсекает ряды старше N дней. Проверка на том же запросе: с `--prefer-fresh` в топе оказываются
`pmuptbovs`, `pmptbik` и `pmbgztb` — «Бетон, готовый для заливки (товарный бетон)», тыс. м³, август
2026; с `--max-age-days 90` результат тот же и без устаревших рядов вовсе.

**Исправлена частота продуктовых рядов.** У 12 420 метрик «Промпродукция» стояла квартальная частота
(наследие маппинга), хотя ряд месячный: переведены на месячную частоту. Карточки показывают прежнее
значение до следующей пересборки — тексты поиска для этих метрик обновятся вместе с ней.

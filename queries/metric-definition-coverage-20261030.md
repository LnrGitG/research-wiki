# Определения метрик: покрытие каталога (30.10.2026)

## Зачем это, а не «17 метрик»

Семантический слой был собран на 17 метриках — это пилотная витрина, а не
целевой охват. Реальный универсум каталога по состоянию на 30.10.2026:

| Срез | Значение |
|---|---|
| активных метрик (`status='active' AND is_active`) | 3 434 |
| из них с наблюдениями (без `rejected`/`superseded`) | 3 387 (98,6 %) |
| карточек с описанием (`derived.metric_card`) | 3 169 (3 165 с вектором) |
| определений до правки | 49 метрик = 1,4 % активных |
| оперативный контур: свежие (в пределах допуска частоты) месячные и квартальные | 1 845 |
| из них с определением до правки | 11 |

Частоты активных: M 2 358, Q 831, A 221, D 13, W 11. Уровень: федеральных
2 373, региональных 796. Область ряда: «только страна» 2 299, «страна и
субъекты» 685, «только субъекты» 154.

Смысл дефекта: 3 387 рядов доступны по коду, но у 3 338 из них не было
зафиксировано, что именно означает число, в каких единицах и с какими
оговорками. Именно на этом месте возникали известные ошибки — накопительный
итог принят за квартал (`vbved_reg_m`), индекс к предыдущему месяцу принят за
проценты г/г (`kep1_14`), сдвиг месяцев (`cbrmon`), дубли удвоили сумму
(`superseded`-строки).

## Что сделано

Скрипт `scripts/build_metric_definitions.py`: для каждой активной метрики с
наблюдениями, у которой определения не было, пишется редакция 1 в статусе
`draft`.

- текст — из карточки: имя, описание, единица, частота, источники, охват
  (число наблюдений, регионов, период);
- `unit_canonical` — из `catalog.unit.name_ru`;
- `caveats` — по правилам префиксов кода (только проверенные дефекты) плюс
  общая оговорка «черновик автогенерации, не сверено с первоисточником»;
- `content_hash` — sha256 по каноническому JSON полей (64 hex, как у ручных
  редакций);
- `owner='auto-draft'`, `source_path='auto:derived.metric_card'`.

Статус `official` скрипт не ставит никогда: подтверждение — отдельная работа
со сверкой.

Приёмка (фактические значения из БД после прогона):

- вставлено **3 338** строк, всего в `catalog.metric_definition` 3 415 на
  3 387 уникальных кодов;
- покрытие активных с наблюдениями — **3 387 из 3 387**, без определения не
  осталось ни одной;
- статусы: `draft` 3 341, `reviewed` 52, `official` 22;
- `content_hash` длины 64 у всех 3 415 строк;
- идемпотентность: повторный `--apply` печатает «нечего добавлять»;
- точка возврата: `attic/metric_definition_before_20261030-133806.csv.gz`
  (77 строк).

Оговорки сработали так: `cbrmon` — 1 372 (месяцы сдвинуты на +1, исправлено
17.10.2026), `fns_1nom`/`drpotr` — 143 (накопленный итог с начала года),
`kep1_14` — 8 (индекс к предыдущему месяцу), плюс оговорки, написанные ранее
руками для 20 рядов ЕИСЖС (координаты в `sub_dimension`, 7 920 строк на 7 840
пар).

## Что осталось (по приоритету)

1. **`verified_at` — 0 из 3 387.** Черновик не является обязательством:
   сверка с первоисточником нужна по оперативному контуру (1 845 метрик),
   начиная с 22 уже `official` и с шести ипотечных кодов ЦБ. Для ЦБ источник
   `cbr.ru` доступен, для дом.рф/fedstat нужен резидентный канал (C-7).
2. **Цепочка версий.** У 23 кодов по 2–3 редакции (шесть `cbr_izhk_*`,
   `emiss_34118_vvod` и др.), но `supersedes` пуст у всех — «какая редакция
   текущая» пока определяется `max(version)` и статусом, а не связью.
3. **Три пустые единицы** у ручных редакций (`okb`, `pzk`, `zka`) — заполнить
   или пометить «единица не определена источником».
4. **265 активных метрик без карточки** (3 434 − 3 169): ночная пересборка
   `build_metric_cards.py` должна их подхватить; остаток — отчёт дефекта
   каталога, а не тишина.
5. **Семантический слой расширять по контурам**: оперативный (1 845, все с
   определениями `official` после сверки) и исследовательский (всё с
   `draft`), с обязательным JOIN на `catalog.metric_definition`, чтобы число
   нельзя было показать без определения.

## Воспроизведение

```bash
python3 scripts/build_metric_definitions.py --check                 # посчитать
python3 scripts/build_metric_definitions.py --check --tier operational
python3 scripts/build_metric_definitions.py --apply                 # записать
```

Тяжёлый агрегат (7,9 млн наблюдений) берёт соединение с `work_mem=1GB` на
сессию — см. инцидент `DiskFull` 30.10.2026 в `log-tech.md`.

Цель: из 2 438 метрик отобрать ядро полезных рядов для оперативного анализа и nowcasting, отбросив дубли, артефакты парсинга и ряды без сигнала.

- ДОМ.РФ (120): сток/флоу строительства, продажи, готовность, разрешений сток/флоу, ДДУ, индекс цен, сделок, реализация квартир

Уровень C — частота: год/квартал/месяц для одной и той же KPI (например ВВП: kep1_1 level годовой + kep1_12 level квартальный; дубли-имена с одинаковой частотой — 71 случай).

Уровень D — разрезы: `region` (102) × `sub_dimension` (в ДОМ.РФ-стоке sub_dimension хранит «разрез: регион → № объекта, строка, лист» — 21 618 наблюдений с разрезами, 104 метрики, до 100 метрик по Чукотскому АО — это пообъектная детализация, не временные ряды).

Уровень E — версии: assessment_type (final/preliminary) × release (27 релизов; 7 346 (метрика, регион, период) имеют >1 релиза — правила выбора свежего release_id обязательны).

## 3. Что отсекается (гигиена, найдено фактически)

1. **Артефакты парсинга**: 102 метрики, где ≥50% наблюдений — одно и то же значение при длине ряда ≥12 (счётчики/строки-заглушки из прайс-листов, `cou`, `vol` и т.п.).
2. **Не-временные разрезы**: метрики с sub_dimension «разрез: …» (104) — это объектный уровень ДОМ.РФ, в ряды их не включать (или агрегировать по периоду отдельно).
3. **Умершие ряды**: 601 метрика с последней точкой до 2024-01-01 (из них stage7 — 396, rosstat_panel — 69) — кандидат на `status='deprecated'`.
4. **Методологические разрывы**: 209 метрик с флагами `методологический_разрыв_2013/2016/2017` — не удалять, но пометить в comparability-таблице (`meta.series_comparability` пуста — заполнить).
5. **Дубли имён**: 1 065 пар с одинаковым name_ru (в основном level/yoy и межчастотные копии); 347 групп после нормализации «— level/yoy (КЭП…)» — построить canonical-справочник.
6. **Короткие ряды**: 26 месячных с <12 точками; 1 057 метрик всего с <12 наблюдениями — в срез не входят, но не удалять (новые ряды).

## 4. Статистическая валидация рядов (по самим рядам)

Для каждого ряда (метрика × регион × частота, final, последний release) считать:

A. **Полнота и свежесть**: n_периодов, последняя дата, доля пропусков внутри диапазона.
B. **Дисперсия и логика**: коэффициент вариации (CV = σ/μ); правило отсечки — CV < 1% при n ≥ 12 (константа/ошибка парсинга) → в архив. Порог смягчать для индексов (там тренд, но проверять монотонность базиса).
C. **Автокорреляция lag-1** (для месячных ≥36 точек): |AC1| < 0.2 и CV < 5% — сигнал шум/брак; AC1 > 0.95 при ненулевом тренде — гладкий уровень (ок для level, подозрительно для yoy).
D. **Число структурных сдвигов**: тест на скачок уровня (сравнение медиан до/после каждой точки, |Δlevel| > 5σ) — кандидаты на разрывы (сверить с флагами 2013/2016/2017).
E. **Выбросы**: точки за 4σ от локального окна (±6 периодов) — список для ручной сверки с источником.
F. **Сезонность**: амплитуда месячных индексов (max/min по календарным месяцам после дифференцирования) — определяет, нужен ли SA-поправленный вариант ряда.
G. **Отрицательные значения** в уровневых рядах, где они невозможны (площадь, объём, число договоров): 7 месячных рядов с отрицательными значениями — сверка.

Выход этапа — таблица `derived.metric_audit` (metric_id, n, cv, ac1, n_breaks, last_period, verdict: core/useful/archive/junk).

## 5. Целевые срезы (полезное ядро)

Срез «Оперативный мониторинг» (обновляется ежемесячно): 209 метрик с данными с июля 2026, теги domrf_*/cbr_* + stage5 (467 месячных с ≥12 точками и свежестью — верхняя граница). Правило: месячная частота, последняя точка ≤2 мес, финальная оценка.

Срез «Nowcasting СМР/ИКВ» (под задачи профиля): эскроу (stock/flow), ДДУ, кредиты ИЖК, ввод жилья, разрешений сток/флоу, готовность, реализация квартир, цены (itzdr), курс, КЭП 1.1/1.7/2.2/4.x yoy — примерно 60–80 рядов; это рабочее множество для bridge-модели.

Срез «Региональная панель»: rosstat_panel (189 метрик × 96 регионов, годовая) + ДОМ.РФ региональные разрезы после агрегации sub_dimension по периоду (203 месячных ряда покрывают >30 регионов).

Срез «Макроконтекст»: КЭП блоки 1 (454), 3 (78), 4 (382) — годовой/квартальный уровень + yoy; чистить от vm* и дублей.

## 6. Проверяемые гипотезы по итогам

- H-A: доля рядов-констант среди stage6 (ввод мощностей) выше, чем среди cbr/domrf — парсинг таблиц «ввод мощностей» порождает строки-заглушки.
- H-B: все ряды с флагом методологического разрыва имеют тест СД > 1 в заявленный год (валидация флагов).
- H-C: preliminary-версии отличаются от финальных <5% в 95% случаев (тогда можно брать любую версию; иначе — правила ревизий).
- H-D: для среза nowcasting ≥80% рядов имеют AC1 > 0.8 и не требуют сезонной корректировки (yoy-формы) — проверка готовности к bridge-модели.

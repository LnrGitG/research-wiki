## Открытый вопрос: свежесть

Критерий приёмки «свежесть ряда в `derived.v_metric_context` — «свежие»» **не выполнен**: получено
`«отстают»` для всех 7 рядов.

Арифметика: `derived.v_metric_card.last_observation = max(period_start)` (не `period_end`), предел для
годовой частоты — 550 дней. Для последнего года 2025 `period_start = 2025-01-01` (предложение, п. 5:
`period_start = YYYY-01-01`, `period_end = YYYY-12-31`), окно свежести закрылось **2026-07-05**, прогон
выполнен **2026-10-16** (отставание 103 дня). Предложение (стр. 129–130) ожидало «свежие» при той же
датировке — это выполняется только до 2026-07-05; похоже, автор полагал, что представление свежести
опирается на `period_end`, тогда как оно опирается на `period_start`.

Порог 550 дней в скриптах не переписывался. Способа получить «свежие» для годового ряда 2025 при
каноничной датировке (`YYYY-01-01`, как в `emiss_registry_ingest.py`) без правки представления нет —
это методическое решение macroeconomist: либо принять «отстают» как честное состояние (сейчас в БД
244 годовых ряда с `last_observation = 2025-01-01` находятся ровно в том же статусе), либо сменить
соглашение о датировке годовых наблюдений для обследований.

## Границы и замечания

- Расхождение знаменателя (ОБДХ против зарплатной статистики: 56 997 руб. на члена в месяц по
  Башкортостану против 49 086 руб. по России) зафиксировано, разбирается отдельно, загрузку не блокирует.
- `assessment_type` — из словаря БД (`final` / `preliminary`), значение `'survey'` из предложения в базе
  не используется; год, закрытый следующим выпуском, помечен `final`, последний год выпуска — `preliminary`.
- `observation_status = 'superseded'` — новое значение статуса (словарь был `validated` / `raw` /
  `rejected`), ограничения `CHECK` на столбце нет.
- Проверка `fetch_context` по запросу «платёжная нагрузка Башкортостан» возвращает также посторонние
  метрики слова «нагрузка» (`kep4_126`, КЭП 4.1) — это ранжирование существующего поиска, не дефект загрузки.

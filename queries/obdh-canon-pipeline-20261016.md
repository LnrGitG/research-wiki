## Открытый вопрос: свежесть

Критерий приёмки «свежесть ряда в `derived.v_metric_context` — «свежие»» **не выполнен**: получено
`«отстают»` для всех 7 рядов.

Арифметика: `derived.v_metric_card.last_observation = max(period_start)` (не `period_end`), предел для
годовой частоты — 550 дней. Для последнего года 2025 `period_start = 2025-01-01` (предложение, п. 5:
`period_start = YYYY-01-01`, `period_end = YYYY-12-31`), окно свежести закрылось **2026-07-05**, прогон
выполнен **2026-10-16** (отставание 103 дня). Предложение (стр. 129–130) ожидало «свежие» при той же
датировке — это выполняется только до 2026-07-05; похоже, автор полагал, что представление свежести
опирается на `period_end`, тогда как оно опирается на `period_start`.

Порог 550 дней в скриптах не переписывался. Способа получить «свежие» для годового ряда 2025 при
каноничной датировке (`YYYY-01-01`, как в `emiss_registry_ingest.py`) без правки представления нет —
это методическое решение macroeconomist: либо принять «отстают» как честное состояние (сейчас в БД
244 годовых ряда с `last_observation = 2025-01-01` находятся ровно в том же статусе), либо сменить
соглашение о датировке годовых наблюдений для обследований.

## Границы и замечания

- Расхождение знаменателя (ОБДХ против зарплатной статистики: 56 997 руб. на члена в месяц по
  Башкортостану против 49 086 руб. по России) зафиксировано, разбирается отдельно, загрузку не блокирует.
- `assessment_type` — из словаря БД (`final` / `preliminary`), значение `'survey'` из предложения в базе
  не используется; год, закрытый следующим выпуском, помечен `final`, последний год выпуска — `preliminary`.
- `observation_status = 'superseded'` — новое значение статуса (словарь был `validated` / `raw` /

- Проверка `fetch_context` по запросу «платёжная нагрузка Башкортостан» возвращает также посторонние
  метрики слова «нагрузка» (`kep4_126`, КЭП 4.1) — это ранжирование существующего поиска, не дефект загрузки.

## Ревизия 20.10.2026: знаменатель прокси — денежный доход (заменяет разделы «Карточки», «Приёмка производной», «Чтение», «Свежесть»)

Поправка постановщика (`~/macroeconomist/queries/amendment_85ca5ed3.md`, комментарии к задаче от
20.10.2026) заменяет знаменатель производной: вместо располагаемых ресурсов — денежный доход
домохозяйства на члена в месяц.

Причина содержательная: лист 1.1 раскрывает структуру ресурсов, и ресурсы = денежный доход +
натуральные поступления + привлечённые средства и израсходованные сбережения. Последняя компонента
делает меру круговой: поток платежей делится на доход, который сам содержит новые заимствования.
По 2025 году доля привлечённых средств у Башкортостана максимальна среди 85 субъектов (18,43 %
против 6,50 % по России), поэтому ресурсный прокси занижал нагрузку республики сильнее всего —
11,78 % и 63-е место вместо 15,22 % и 36-го.

### Что изменено в загрузчике (`scripts/ingest_obdh.py`)

- добавлены три наблюдаемые метрики: `obdh_money_income_pc_month` (`rub_per_person_month`),
  `obdh_borrowed_share` и `obdh_inkind_share` (`pct`). Денежный доход в рублях в бюллетене не
  публикуется — он считается как ресурсы × доля денежного дохода / 100, что записано в `notes`
  наблюдения;
- `formula_text` основной производной переписан на денежный доход (937 символов);
- ресурсный вариант сохранён как контрольный отдельной метрикой `proxy_pdn_resources_control`
  (`metric_type = 'derived_control'`), значения помечены `quality_flags = {incl_borrowed_funds,
  control_variant}` и `notes`. Прежние строки релиза 186 переведены в контрольную метрику без
  переписывания значений; релиз 186 переименован в «ОБДХ прокси ПДН по ресурсам (контрольный вариант)»;
- идемпотентность: в хеш производной добавлена версия формулы (`PROXY_VERSION = v2_money_income_2026-10-20`),
  поэтому смена знаменателя создаёт новый релиз 363, а не молча переписывает прежний;
- ревизия производной получила отдельный шаг: строки того же региона/периода из старого релиза
  помечаются `superseded` (значения не переписываются);
- выпуск, уже загруженный по хешу, теперь не пропускается целиком, а дозаполняется по новым
  метрикам (иначе новые карточки не получили бы историю 2023–2025 из релизов 184/185).

### Свежесть: решение принято, критерий переформулирован

Постановщик 20.10.2026 принял вариант 1 ревью: статус «отстают» — честное состояние годового ряда,
а не дефект загрузчика. AC5 читается как «значения за 2025 год есть, релиз распознан, дата наблюдения
2025-01-01 по канону `period_start`» — выполнено. Смена датировки на `period_end` отклонена (затронула бы
262 годовых ряда всего канона). Системный дефект зафиксирован отдельно: 244 из 262 годовых рядов с
`last_observation = 2025-01-01` находятся в статусе «отстают»; предложение поднять допуск годовой
частоты до 730 дней вынесено владельцу и в границы этой задачи не входит.

### Дрейф витрины закрыт

`scripts/build_context_views.py` содержал плоскую логику свежести 45/120 (против живой
частотно-зависимой в `scripts/fix_context_freshness.py`, A=550) и одним прогоном мог откатить витрину.
Файл помечен устаревшим: баннер в docstring и блокировка запуска без `FORCE_BUILD_CONTEXT_VIEWS=1`.
Скрипт не перепрогонялся.

### Замечание о чтении

`ops.fetch_context` фильтрует только `observation_status = 'rejected'`, поэтому в выдачу попадают и
`superseded`-строки прежнего релиза (значения те же). Это свойство функции чтения, а не загрузчика;
правка `ops.fetch_context` в границы задачи не входила.

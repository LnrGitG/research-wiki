# Восстановление измерения `subsection` в панели регионов

## Проблема
Панель `staging.regions_panel__panel` (308 952 строки) собиралась из сборника
«Регионы России 102», но при загрузке терялась колонка `subsection` — она
различает строки внутри одного показателя. Из-за этого под одним кодом
оказывалось несколько значений, и они **схлопывались**: 104 874 строки панели
утратили различие между направлениями.

Пример до восстановления — показатель `Y477050017` (инвестиции в основной
капитал по направлениям), Вологодская область, 2024 год: шесть безымянных
чисел (8.6 … 80.2) без указания, что каждое означает.

## Источник
`raw/rosstat/regions_collection_102/data_regions_collection_102_v20260313_csv.zip`
(официальный сборник «Регионы России. Социально-экономические показатели 2023»,
версия v20260313).

Ключевые колонки: `indicator_code`, `indicator_name`, `subsection`,
`object_name`, `year`, `indicator_value`, `indicator_unit`, `source`.

`subsection` принимает два вида значений:
- **текстовые** — направление («Строительство: здания и сооружения»,
  «Распределение по полу: женщины»);
- **коды-легенды** — например `CD` для валового накопления основного капитала
  (расшифровка — в `comment`).

## Диагностика
| проверка | результат |
|---|---|
| значений панели без пары в первоисточнике | 0 |
| кодов панели без пары в первоисточнике | 0 |
| строк первоисточника по ключам панели | 413 850 |
| строк панели | 308 952 |
| разница (схлопнуто) | 104 898 |
| различных подписей `subsection` | 245 |

**Почему не соединение.** Первоисточник содержит по тем же ключам *больше*
строк, чем панель, — значит схлопывание произошло при загрузке, и `JOIN` по
`(код, регион, год, значение)` вернул бы те же 308 952 строки, оставив
схлопнутость. Проверка соединением дала 5% неоднозначных строк (15 512)
на значениях-заполнителях `-99999999` и подобных, где одна цифра отвечает
сразу нескольким подписям. Поэтому восстановление выполнено **пересборкой**
из первоисточника.

## Решение
`scripts/load_panel_subsection.py` — загрузка целевых CSV сборника в
`staging.panel_subsection` (только строки с непустым `subsection`, 712 780 строк).

`scripts/expand_panel_subsection.py` — сборка `staging.panel_expanded`:
строки первоисточника, у которых ключ `(код, регион, год)` присутствует в
панели. Встроены проверки полноты включения.

`scripts/load_panel_missing.py` — адресная догрузка: определяет коды без
подписи и берёт из архива только те CSV, где они лежат (4 файла вместо 40).

## Результат
```
panel (схлопнуто):   308 952
panel_expanded:      413 850   (+104 898)
подписей subsection:     245
ключей без раскрытия:      0
значений без пары:         0
```

Пример после восстановления (Вологодская область, 2024, `Y477050017`):
```
80.2  Приобретение новых основных средств: машины и оборудование
54.9  Строительство: здания и сооружения, расходы на улучшение земель
50.2  Модернизация и реконструкция: здания и сооружения
49.6  Модернизация и реконструкция: машины и оборудование
42.9  Строительство: машины и оборудование, хозяйственный инвентарь
 8.6  Приобретение новых основных средств: здания и сооружения
```

## Замечания для дальнейшей работы
1. **Заполнители.** 27 807 строк панели содержат коды-заполнители
   (`-99999999`, `-77777777`) вместо значений — это не пропуски данных, а
   условные обозначения Росстата; при анализе их надо исключать явно.
2. **`subsection` — не всегда текст.** Часть подписей это коды-легенды (`CD`);
   расшифровка лежит в `comment`.
3. **Многотомность.** «Регионы России. Социально-экономические показатели»
   разбит на 20+ CSV (`data_01…data_21_socio_economic`); при выборке по кодам
   нужно проверять все тома, а не первый найденный.
4. **Один код — разные показатели.** `indicator_code` в сборнике не уникален
   для показателя: под `Y477020001` лежат и «Распределение по полу», и
   «Удельный вес в численности занятых», различаемые `indicator_name`.

## Восстановление
```sql
DROP TABLE staging.regions_panel__panel;   -- схлопнутая версия
-- первоисточник: staging.panel_subsection
-- раскрытая версия: staging.panel_expanded
```

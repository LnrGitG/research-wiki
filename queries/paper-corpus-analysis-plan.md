## Целевая схема таблицы

Поля на русском; в скобках — машинное имя колонки в БД.

| Русское название | Колонка | Тип | Источник заполнения |
|---|---|---|---|
| Название | `title_ru` | text | фронтматтер / текст / перевод |
| Оригинальное название | `title_orig` | text | `t` из JSON, фронтматтер |
| Ссылка на источник | `source_url` | text | DOI → `https://doi.org/...`, иначе URL |
| DOI | `doi` | text | фронтматтер, текст, Crossref по названию |
| Авторы | `authors` | text[] | фронтматтер, Crossref |
| Год | `year` | int | фронтматтер, Crossref |
| Издание | `venue` | text | фронтматтер, Crossref |
| Выводы | `findings` | text | секции conclusions/abstract перевода |
| Источники и данные | `data_sources` | text | поле `data` + разбор текста |
| Методы | `methods` | text | поле `models` + разбор текста |
| Список литературы | `references` | jsonb | разбор секции литературы |
| Ссылка на первичный PDF | `pdf_url` | text | `core.file_registry.uri` |
| Тип документа | `doc_type` | text | `paper` / `report` / `translation` |
| Наличие перевода | `has_translation_ru` | bool | есть ли `.RU.md` |
| Ссылка на статью в вики | `wiki_page_url` | text | путь к `.md` |
| Статус обработки | `parse_status` | text | ok / partial / needs_review |

## Развилка, которую надо решить до старта

**Ссылка на PDF.** Бакет `wiki-research` приватный. Прямой URL файла
работать не будет. Три варианта:

**Вариант A — presigned URL по требованию.** Функция генерирует временную
ссылку (например, на час). Плюс: файл остаётся приватным. Минус: в таблице
хранится не ссылка, а путь, и ссылку надо запрашивать.

**Вариант B — отдельный публичный бакет только для PDF корпуса.** Плюс:
ссылка постоянная, работает в любой таблице и в Obsidian. Минус: PDF
становятся публичными — а это чужие статьи под копирайтом. **Юридически
рискованно, не рекомендую.**

**Вариант C — ссылка-указатель вместо файла.** В таблице колонка «как
получить PDF»: путь в бакете плюс команда. Плюс: безопасно, честно. Минус:
не кликабельна для внешнего читателя.

Рекомендую **A для себя** (кликабельно внутри сетапа) и **C как значение по
умолчанию** (безопасно для любого потребителя). Колонок две: `pdf_path`
(путь) и `pdf_url` (presigned, обновляемая).

## План работ

### Фаза 0. Разведка и точка возврата (полдня)

Инвентаризация: свести фронтматтер 314 статей, `paper-details.json`,
`data/catalog.yaml`, аннотации (16 файлов), библиографии — в один
промежуточный JSON. Посчитать пофайловую заполненность каждого целевого
поля. Точка возврата: git-тег.

Результат: таблица «поле × сколько записей заполнено» и список дыр, по
которым нужен разбор текста.

### Фаза 1. Названия, авторы, год, издание, DOI (день)

Порядок источников: фронтматтер → Crossref по DOI → Crossref по названию →
разбор первой страницы markdown. Crossref через `habanero`, ключ не нужен,
но обязательны вежливые паузы (у них лимит и бан за агрессивность).

Осторожно: сопоставление по названию даёт ложные срабатывания. Правило —
при совпадении по названию сверять год и фамилию первого автора; при
расхождении оставлять пусто и помечать `needs_review`, а не подставлять
неверное.

Результат: заполненные `title_orig`, `authors`, `year`, `venue`, `doi`,
`source_url`.

### Фаза 2. Выводы и методы (день)

**Выводы:** из перевода `.RU.md` (161 файл) — секции «Выводы»,
«Заключение», «Основные результаты»; при отсутствии — из abstract. Для
непереведённых — из английского оригинала теми же шаблонами.

**Методы:** поле `models` из JSON (465 записей, 74%) плюс разбор секций
«Методология», «Данные и метод», «Эмпирическая стратегия».

**Данные:** поле `data` (463, 73%) плюс поиск упоминаний источников
(Росстат, ЦБ, ФНС, ДОМ.РФ, ЕМИСС, OECD, Eurostat, BIS и другие) регулярками
по словарю.

Это самая содержательная фаза: она превращает технический индекс в
читаемую таблицу. Здесь же — обязательная проверка на выдумку: каждое
значение извлекается из текста, а не додумывается моделью. Если поле не
найдено — пусто и `partial`, не «правдоподобная догадка».

### Фаза 3. Список литературы (полтора-дня)

Разбор секции литературы из markdown. Формат ссылок разный, поэтому:
регулярки для DOI (`10.\d{4,}/...`) и URL, затем Crossref для дополнения,
остальное — как текстовая строка.

Важно: **сейчас секция есть только у 47 статей из 314.** Для остальных
варианты — разбирать PDF напрямую (`pdfplumber` по последним страницам) или
оставить пусто. Предлагаю второй: разбор PDF дорог и даст шум. Библиографии
`bibliography_references.md` при этом дают около 993 записи — их можно
связать по DOI.

Результат: `references` как jsonb — массив объектов `{текст, doi, url,
год}`, а не одна строка.

### Фаза 4. Связка PDF и хранилище (полдня)

### Фаза 5. Загрузка в БД YC (день)

## Риски и ограничения

**Сопоставление по названию даёт ошибки.** Crossref найдёт не ту работу —
особенно для русскоязычных статей и отчётов без DOI. Правило: не
подставлять при сомнении, помечать на проверку.

**Полнота будет неполной — и это нормально.** Авторов и год удастся
заполнить примерно для 60–70% корпуса, DOI — для меньшей части. Обещать
100% нельзя. Честная цель: 100% названий, 70% авторов и лет, 50% DOI,
100% ссылок на PDF там, где файл есть.

**Разбор PDF дорог.** 314 файлов, некоторые крупные. Если пойдём разбирать
списки литературы напрямую из PDF — это часы работы и много шума. Я за то,
чтобы этого не делать на первой итерации.

**Дубли в корпусе.** Есть статьи с русскими именами файлов, есть латинские,
есть пары «оригинал + перевод», есть близкие названия. Нужна дедупликация
по DOI, затем по нормализованному названию плюс году.

**Права на PDF.** В бакете лежат чужие статьи. Публичная ссылка на них —
вопрос не технический, а правовой. Поэтому и предлагаю presigned или
путь-указатель, а не публичный бакет.

**Объём работы.** Пять-шесть дней на всё, при условии что фазы идут
последовательно. Фазы 1–2 дают основную ценность; 3–4 можно отложить.

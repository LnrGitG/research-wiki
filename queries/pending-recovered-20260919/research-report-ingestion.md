## Recurring radar/digest artifacts (cron output)
A scheduled literature radar is a **recurring artifact**, not a one-off:
its report file (`queries/research-radar-<date>.md`), the hypotheses patch,
and the cron session's summary all exist on disk. When the user asks to
repeat or review a report, READ THE ARTIFACT first and summarize from it;
deliver as connected narrative prose (one paragraph per work: what it does,
what it found, what it means for the hypotheses), never as a bare table
restatement. A table is fine as an appendix inside the wiki file, but the
chat reply must restate findings in full sentences — the user reads these
re-reports for understanding, not for a diff. Verify the file exists and
matches the cron session before quoting numbers from the session transcript

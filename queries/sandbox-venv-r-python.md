`research-db`. Все утверждения проверены запуском на самой ВМ.

## История установки R: две ошибки, обе поучительные

Задача выглядела просто — «поставить R и пакеты». Фактически пришлось
разобраться в двух ловушках, каждая из которых стоила времени.

### Ловушка 1: R-пакеты собираются из исходников часами

Первая попытка поставить пакеты через `install.packages()` дала 55 скачанных
`.tar.gz` — то есть **исходники**. На 20% vCPU компиляция `fixest`, `bsts`,
`rugarch` (каждый из них тянет C++/Fortran) заняла бы часы. Установка висела
на скачивании и компиляции, библиотека оставалась пустой.

**Решение — бинарные пакеты через apt.** Проверены три источника:

| Источник | Результат |
|---|---|
| Posit Package Manager | **отдаёт только исходники** для R 4.6 (404 на бинарник) |
| CRAN напрямую | исходники |
| **r2u** (`r2u.stat.illinois.edu`) | **6 100 бинарных пакетов** для noble — победа |

Ключ репозитория брался с keyserver.ubuntu.com по keyid `A1489FE2AB99A21A`
(на самом r2u файла ключа нет — только `Release.gpg`).

### Ловушка 2: версии R не совпали

r2u собирает пакеты под **R 4.4+**, а apt-репозиторий Ubuntu даёт **4.3.3**.
Установка падала с «held broken packages», потому что `r-cran-fixest` требует
`r-base-core >= 4.4.0`.

**Решение — обновить R из CRAN.** Подключён репозиторий
`cloud.r-project.org/bin/linux/ubuntu noble-cran40` (ключ `marutter_pubkey.asc`),
R обновлён 4.3.3 → **4.6.1**. После этого бинарники r2u встали.

**Вывод на будущее:** на новой машине порядок действий — сперва R из CRAN,
потом r2u, потом `apt-get install r-cran-*`. Обратный порядок даёт ловушку 2,
а отсутствие r2u — ловушку 1.

## Что удалось обойти, а что нет

**`IRkernel` (R-ядро для Jupyter) заработал после обновления R.** Сначала
конфликтовал по версии — та же ловушка 2, «held broken packages». После
перехода на 4.6.1 встал, и в песочнице доступны **два ядра: Python 3 и R**,
переключаемые внутри одной тетради:

```
$ jupyter kernelspec list
  python3    ~/.venvs/sandbox/share/jupyter/kernels/python3
  ir         /usr/share/jupyter/kernels/ir
```

**Доступ к БД из R** обеспечен пакетом `RPostgres` (в r2u есть, 1.4.10).
Проверено: R читает `research_wiki` и видит 314 карточек, 16 таблиц в `core`.

Тонкость чтения: `count(*)` в PostgreSQL возвращает `bigint`, и R читает его
как `double` с потерей — `314` превратилось в `1.55e-321`. Правильно
приводить тип в запросе: `SELECT count(*)::int AS n ...`.

**Пакеты, которые требуют сборки и в r2u отсутствуют** (`bsts`, `MARSS`,
`fable`, `feasts`, `tsibble`), ставятся через `install.packages()` — их
сборка на 20% vCPU идёт минутами, а не часами, потому что зависимости
уже стоят бинарниками из r2u.

## Доступ с ноутбука: пошагово

Порт 8888 на ВМ **наружу закрыт** (группа безопасности `ssh-access-sg`
разрешает только 22 и 5432). Доступ идёт через SSH-туннель.

### Шаг 1. Получить ключ

Приватный ключ лежит на VPS: `~/.ssh/id_yc`. Скопировать на ноутбук:

```
# Mac / Linux
scp lnr@<адрес-VPS>:~/.ssh/id_yc ~/.ssh/id_yc
chmod 600 ~/.ssh/id_yc

# Windows (PowerShell)
scp lnr@<адрес-VPS>:~/.ssh/id_yc $env:USERPROFILE\.ssh\id_yc
icacls $env:USERPROFILE\.ssh\id_yc /inheritance:r /grant:r "$($env:USERNAME):(R)"
```

Права `600` обязательны: SSH отказывается работать с ключом, доступным
посторонним. Публичная часть ключа — `ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIA3clGW99S4JRsnHeJrAAKqXMnG1MBnDp5g0Wd7UzYRL lnr@research-wiki-yc`.

### Шаг 2. Запустить песочницу на ВМ

Она не держится постоянно: 98 МБ памяти впустую, когда разведки нет.

```
ssh -i ~/.ssh/id_yc ubuntu@89.169.168.214
~/sandbox_jupyter.sh start
```

Скрипт создаёт токен (один раз, дальше переиспользует), поднимает сервер
и печатает адрес. Другие команды: `stop`, `status`, `token`.

### Шаг 3. Подключиться с ноутбука

Готовый скрипт `connect_sandbox.sh` (лежит на ВМ) делает всё сам: получает
токен, поднимает туннель, открывает браузер.

```
scp -i ~/.ssh/id_yc ubuntu@89.169.168.214:~/connect_sandbox.sh .
chmod +x connect_sandbox.sh
./connect_sandbox.sh
```

Если скрипт не нужен — вручную одной командой:

```
ssh -i ~/.ssh/id_yc -N -L 8888:127.0.0.1:8888 ubuntu@89.169.168.214
```

Затем в браузере ноутбука: `http://localhost:8888/lab?token=<токен из start>`.

**Туннель закрывать нельзя** — пока он работает, страница доступна; Ctrl+C
разрывает доступ. Это не недостаток: так соединение не висит открытым
без присмотра.

### Доступ с телефона

Тот же принцип, только SSH-клиент мобильный. Termius, Termux, JuiceSSH умеют
перенаправление портов — в настройках соединения указывается
`8888:127.0.0.1:8888`, затем браузер телефона открывает `localhost:8888`.

### Постоянный туннель (необязательно)

Если заходить часто — можно завести юнит по образцу уже работающих
(`pg-tunnel` на 15432, `hermes2-tunnel` на 18642): тогда туннель держится
на VPS постоянно, а с ноутбука достаточно открыть `localhost:18888`. Минус —
соединение к ВМ висит всё время, даже когда не нужно.

## Где что лежит

| Что | Путь |
|---|---|
| venv песочницы | `~/.venvs/sandbox` |
| Управление песочницей | `~/sandbox_jupyter.sh` |
| Подключение с ноутбука | `~/connect_sandbox.sh` |
| Токен доступа | `~/.venvs/sandbox/.jupyter_token` (600) |
| Лог сервера | `~/.venvs/sandbox/jupyter.log` |
| Рабочий каталог (тетради) | `~/research-wiki-private` |
| R-пакеты | `/usr/lib/R/site-library` (системные, из apt — 123 пакета) |

Тетради ложатся прямо в главный репозиторий — рядом с данными и скриптами.
Их видно в git, можно коммитить вместе с анализом.

## Что стоит знать про ограничения

**Память.** Песочница в простое — 98 МБ. При работе с большими таблицами
растёт: чтение 200 тыс. строк дало 71 МБ в памяти pandas. Доступно 7 ГБ,
так что запас есть, но при таблицах в миллионы строк стоит переходить на
DuckDB (`duckdb` 1.5.5 установлен) или polars — оба читают Parquet/CSV без
загрузки всего в память.

**Процессор.** 20% vCPU, но burst работает: замер показал 4 потока по 6 с
за 6,2 с. Для разведки хватает; для тяжёлых бутстрэпов или ML-обучения —
может оказаться тесно.

**R против Python.** Оба стоят. Python — 17 библиотек в отдельном venv.
R — системная 4.6.1 с пакетами из apt. В тетрадях доступны оба ядра:
Python и R (через IRkernel), можно переключать в одном документе.

**Что не сделано.** Юнит автозапуска песочницы сознательно не заводился —
разведка ручная, держать сервер постоянно незачем.

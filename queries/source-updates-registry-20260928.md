# Реестр обновления источников: первая версия и первые выводы (28.09.2026)

## 1. Зачем это

В реестре источников владельца 60 позиций с ежемесячной периодичностью, а cron-джобов в Hermes
тринадцать. Разрыв закрывался вручную и не был виден: не было места, где записано, что и с какой
периодичностью обновляется, когда обновлялось в последний раз и чем именно. Добавлять четырнадцатый
джоб бессмысленно — это не масштабируется; нужна таблица «источник → периодичность → чем обновляется
→ когда последний успех».

## 2. Что сделано

**Реестр `data/source_updates.yaml`** — 16 позиций в едином формате: код, название, тип
(`auto` — джоб Hermes, `remind` — напоминание владельцу, `manual` — руками), идентификатор джоба,
расписание, периодичность, скрипт обновления, ссылка на источник, куда ложатся данные, заметки.
Заполнен по фактическому состоянию: тринадцать существующих джобов плюс позиции, которые обновляются
руками или напоминанием (ЕИСЖС, iminfin, RFSD, региональный батч ЕМИСС).

**Планировщик `scripts/source_updates.py`** — читает реестр, состояние авто-джобов берёт из
`~/.hermes/cron/jobs.json` (дата и статус последнего прогона), считает просрочку относительно
заявленной периодичности. Ничего не запускает: сначала реестр должен быть выверен владельцем.

```
python3 scripts/source_updates.py             # статус всех позиций
python3 scripts/source_updates.py --due       # только просроченные
python3 scripts/source_updates.py --run fns_1nom
python3 scripts/source_updates.py --coverage  # сопоставление с реестром владельца
```

## 4. Покрытие реестра владельца — предварительная оценка

Сопоставление по ключевым словам источника даёт: из **60** ежемесячных позиций **44** отнесены к
позициям с зарегистрированным обновлением, **16** — без механизма. Оценка предварительная, потому что
сопоставление по источнику («Сайт Банка России») слишком грубое: один и тот же издатель обслуживает
и собираемые, и несобираемые ряды. Поэтому список ниже — не приговор, а очередь на ручную выверку.

Позиции без механизма обновления (примеры): число вакансий и резюме hh.ru; исполнение бюджетов
бюджетной системы РФ (Электронный бюджет); исполнение федерального бюджета РФ (Минфин); инфляция
в регионах ЦБ; данные опросов мониторинга предприятий; процентные ставки по кредитам и депозитам.
Часть из них закрывается ближайшими источниками (инфляция в регионах — региональным срезом,
мониторинг предприятий — джобом мониторинга ЦБ), часть действительно не собирается (hh.ru требует
регистрации приложения, Электронный бюджет недоступен с VPS).

## 5. Что дальше

1. Выверить реестр владельцем: какие позиции переводим в `auto` (новый джоб), какие оставляем
   `remind`, какие закрываются уже собираемыми рядами, какие не нужны.
2. Разобраться с ошибкой джоба промышленных индексов — до 13.10 он должен отработать штатно,
   иначе октябрьский набор файлов снова придётся добирать руками.
3. Заполнить `last_ok` для позиций `manual`/`remind` фактическими датами, чтобы просрочка считалась
   и для них.
4. Отдельным шагом — перевести планировщик в режим запуска (`--run` с исполнением) и повесить на
   один недельный джоб, который сам обновляет всё просроченное и отчитывается одной сводкой.

# Инфраструктура сбора данных РФ на Yandex Cloud (вместо mac с 22.09)

## Зачем

Ключевые РФ-источники (ЕМИСС-витрина ИКВ 34129, bo.nalog.gov.ru полный дамп БФО, частично СПАРК/Росреестр) требуют российского резидентного IP — с текущего VPS недоступны (HANDOFF_EMISS_IKV_IFO.md: витрина blocked). Mac Studio с 22.09 отложен (дорого). Yandex Cloud даёт резидентный IP из РФ-датацентра, pay-as-you-go, учётная запись уже есть. [[vnok-nowcasting-design]]

## Вариант A (рекомендуемый): прерываемая ВМ-«сборщик» + Object Storage

**Архитектура:**
1. **Compute Cloud, прерываемая ВМ** (Intel Cascade Lake, 2 vCPU / 4 ГБ): vCPU 20% = 0.58 ₽/ч + RAM 0.3676 ₽/ГБ·ч ≈ **2.6 ₽/час ≈ 62 ₽/сутки** — включается по задаче (start/stop из скрипта или вручную по крону-«будильнику»). Для непрерывного режима с 22.09: 24/7 ≈ 1900 ₽/мес; режим «включил на 2–3 ч в день» ≈ **150–250 ₽/мес**.
2. **Object Storage (STD)** — приёмка дампов: ~1.2 ₽/ГБ·мес → база БФО (оценка ниже) хранится за **~300–1000 ₽/мес**; класс COLD для архивов дешевле (~0.6 ₽/ГБ·мес).
3. **Yandex Disk** — зеркалирование результатов срезов (уже привычный интерфейс, есть в .env-доступах). Бесплатный 100 ГБ или Я.360.
4. **Cloud Functions + Timer** (free tier: 1 млн вызовов + 10 ГБ·ч) — лёгкие фетчеры (ЦБ, Росстат CSV, Wordstat уже идут с VPS) — можно вообще держать на существующем VPS, без затрат.

**Главные задачи на YC-ВМ:**
| Задача | Источник | Оценка объёма |
|---|---|---|
| **Дамп БФО 2001–2026** (bo.nalog.gov.ru) | Абонентское обслуживание или REST-обход по INN-массивам | Полная база — терабайты в XML; **рабочий срез: ОКВЭД F (строительство) + эмитенты → 10–50 ГБ** |
| ЕМИСС витрина ИКВ (34129) + квартальные ИФО 2005–2011 | showdata POST-экспорт | Гигабайты CSV |
| СПАРК срезы (стройка ОКВЭД 41–43) | Веб-выгрузка по фильтрам | CSV, единицы ГБ |
| Росреестр квартальные дампы | Уже есть скрипты — просто перенос на резидентный IP | Существующие объёмы |

**Практичный подход к БФО (обновлено 09.09 после RFSD):** не качать всю базу и не покупать API — использовать:
1. **«Точно-ст» срезы ОКВЭД (открытый YC Object Storage!)** — data_rfsd_152, раздел F (423К фирм × 187 показателей, 85 МБ/год, 2021–2025): качается с VPS без резидентного IP (проверено HTTP 200)
2. **RFSD (Sci Data 2025, doi:10.1038/s41597-025-05150-1)** — 56.6 млн firm-year 2011–2023, Parquet на Zenodo/HuggingFace, CC-BY: полная панель для firm-level H-008 (квартальность нет — годовые, но harmonized + imputed + non-filing)

## Вариант B: Serverless Containers / Functions — полный

Только для лёгких фетчеров: 1 млн вызовов и 10 ГБ·ч/мес бесплатно. Но: (а) таймаут функций ~10 мин — большой дамп БФО не утащить; (б) резидентный IP у Functions общий — гарантий гео-доступа нет (нужен тест). Оставляем как дополнение, не основу.

## Вариант C: постоянная ВМ (не рекомендуется)
24/7 Cascade Lake 2/4 ГБ ≈ 1900–2200 ₽/мес — дороже смысловой нагрузки; оправдан только если появится задача непрерывного парсинга.

## Оценка бюджета (Вариант A)

| Статья | ₽/мес |
|---|---|
| Прерываемая ВМ (3 ч/день) | 150–250 |
| Object Storage 100–300 ГБ (STD+COLD) | 150–500 |
| Исходящий трафик (результаты на VPS/GitHub) | 0–100 (первые 100 ГБ free) |
| **Итого** | **~300–800 ₽/мес** |

Мак — отложен; VPS за рубежом остаётся для LLM-агента/cron/Yandex-Wordstat; YC-ВМ — только для сбора с резидентного IP.

## План внедрения (2–3 вечера)

1. **Создать прерываемую ВМ** (Ubuntu, 2/4 ГБ) — `yc compute instance create --preemptible`; SSH-ключ, python3 + скрипты из репо (git pull research-wiki).
2. **Object Storage bucket** + статический ключ в `.env` (YC_ACCESS_KEY/YC_SECRET_KEY); скрипт-«сгрузчик» через boto3 (s3-совместимый endpoint https://storage.yandexcloud.net).
3. **Пилот-задача 1:** ЕМИСС витрина 34129 (квартальные ИФО ИКВ 2005–2011) — showdata POST с ВМ; проверка доступности с YC-IP.
4. **Пилот-задача 2:** БФО-срез — расширить rsbu_firm_panel.py на массив ИНН (стройка + эмитенты), выкладка в bucket → Yandex Disk.
5. **Оркестрация:** cron на самой ВМ (systemd-timer); результаты — в Object Storage, метаданные — в Yandex Disk/репо.

## Риски и меры

- **Прерывание ВМ** — задачи идемпотентны (checkpoint-файлы в bucket), перезапуск дёшев.
- **Гео-ограничения могут отличаться по подсетям Яндекса** — пилот-тестом проверить все 4 источника в первый же вечер; если какой-то блокирует YC-подсеть (маловероятно), fallback — egress через YC-шлюз или резидентный прокси.
- **Абонентское обслуживание БФО** — платное, только если полный дамп нужен; REST-обход по ИНН бесплатен.
- **Cost-control:** бюджет-алерт YC (Billing → бюджеты) на 1000 ₽/мес.

# Сервисы Yandex Cloud для research-wiki

Проверено 17.09.2026: какие сервисы доступны в аккаунте `cloud-lenarg` и что
из них реально полезно в пайплайне. Цены — с НДС, регион Россия.

## Что уже развёрнуто и работает

| Ресурс | Роль в пайплайне |
|---|---|
| Compute (ВМ `research-db`, 4×20% vCPU / 8 ГБ / 60 ГБ SSD) | PostgreSQL, сборщик, cron-задачи |
| Object Storage (`agent-vm-exchange`) | канал управления ВМ + доставка данных |
| VPC (подсеть, SG `ssh-access-sg`) | сеть, доступ |
| IAM (сервисный аккаунт `compute-as`) | авторизация всех сервисов |

## Сервисы, доступные через CLI

`yc` показывает 38 групп команд; все ключевые проверены как доступные в аккаунте:
compute, storage, vpc, managed-postgresql, managed-clickhouse, managed-opensearch,
datalens, ai-studio, search-api, serverless, dataproc, ydb, kms, dns, cdn,
logging, lockbox, datatransfer, managed-greenplum, managed-redis, managed-kafka,
managed-mongodb, managed-mysql, container-registry, load-balancer и другие.

## Разбор по задачам

### 1. Векторная база по markdown-страницам

Здесь два принципиально разных пути, и выбор важен.

**Путь А — векторный поиск поверх существующего PostgreSQL (рекомендую).**
В базе уже развёрнут PostgreSQL 16 с расширением `pg_trgm`; для векторов нужен
`pgvector`. Схема из архитектуры уже содержит слой embeddings — добавляется
таблица векторов и ivfflat/hnsw-индекс. Плюсы: единая база, транзакционная
согласованность с `observation` (можно искать и по тексту, и по данным одним
запросом), нулевая дополнительная стоимость инфраструктуры, работа через тот же
канал управления. Минус: `pgvector` нужно доустановить (пакет
`postgresql-16-pgvector` в Ubuntu 24.04 доступен).

**Путь Б — YC AI Studio векторизация + Managed OpenSearch.**
Векторизация через AI Studio: **0,0101 ₽ за 1000 токенов**. Оценка для вики:
689 md-файлов, 37.8 млн символов ≈ 15.1 млн токенов → **~153 ₽ разово** для
полной переиндексации. Дешёво. Но кластер OpenSearch для хранения векторов
обходится существенно дороже: минимальный (1 хост) ≈ **7 800 ₽/мес**
(2×100% vCPU + 8 ГБ + 30 ГБ SSD), плюс публичный IP 0,2766 ₽/час ≈ 200 ₽/мес.
Это вторая по стоимости статья после самой ВМ и **не оправдана** для
689 страниц — Postgres справится.

**Путь В — векторизация локальными моделями.** Текущий подход вики
(`paraphrase-multilingual-MiniLM-L12-v2`, 384 измерения) работает на ВМ
бесплатно. AI Studio даёт более сильные модели (в т.ч. мультиязычные), но
разница для поиска по своей вики вряд ли критична.

**Вывод:** pgvector на существующей ВМ. AI Studio-векторизация — как
дополнение, если понадобится семантический поиск по-настоящему
мультиязычный или для больших объёмов.

### 2. Визуализация вместо GitHub Pages — DataLens

**DataLens бесплатен для индивидуального использования** — одно рабочее место
не тарифицируется. Второе и последующие — 990 ₽ за каждое в месяц. Для тебя
(один пользователь) это **бесплатно**.

Что даёт по сравнению с текущим GitHub Pages: интерактивные дашборды с
подключением прямо к PostgreSQL, без сборки статики и без `data-summary.json`
как промежуточного слоя. Сейчас ты строишь Chart.js-графики из заранее
выгруженного JSON и проверяешь их с телефона с оговоркой «кэш → инкогнито».
DataLens убирает и то, и другое: данные тянутся напрямую из базы, дашборд
всегда актуален.

Ограничение: DataLens живёт в веб-интерфейсе YC и требует авторизации; для
**публичного** доступа есть механизм публичных ссылок, но публикация данных
наружу — отдельное решение. Для внутреннего анализа это лучший вариант.

### 3. Библиография с ссылками

Прямого «сервиса библиографии» в YC нет, но есть два полезных компонента.

**Хранение — уже решается схемой.** В архитектуре есть `core.document` и
`core.note` со связями на `metric_id`, `region_id`, `source_id`, `file_id`.
898 записей текущей библиографии (`docs/bibliography.json`, 490 КБ) ложатся
в `core.document` с DOI и связями на страницы вики.

**Обогащение — Yandex Search API.** Цены: отложенные запросы **30,5 ₽/1000**
(днём) и 25,41 ₽/1000 (ночью) против синхронных 488 ₽/1000. Разница в 16 раз —
для пакетного обогащения библиографии (проверка доступности ссылок, поиск
метаданных) брать только отложенный режим. В нём же встроен **Wordstat**:
`GetTop` и `GetDynamics` по 20 ₽/запрос, `GetRegionsDistribution` 50 ₽,
`GetRegionsTree` бесплатно.

Замечание: у тебя уже работает Wordstat через `YANDEX_CLOUD_API_KEY`, и тариф
там другой (лимит 100 зап/час по бесплатной квоте). Платный Search API
открывает региональные распределения запросов — это прямой путь к
региональному nowcast спроса на жильё.

### 4. Obsidian-слой

YC здесь не нужен и не поможет — Obsidian работает локально с файлами.
Но есть смежная польза: **ВМ может держать git-версию вики** и синхронизировать
её, а Obsidian подключается к локальной копии. Плюс, если понадобится доступ
с телефона — публикация через Object Storage как статический сайт (бакет
умеет раздавать статику), вместо GitHub Pages. Стоимость — копейки за хранение
и трафик (первые 100 ГБ/мес бесплатно).

### 5. Что ещё может пригодиться

**Managed PostgreSQL с PITR** — если решишь перейти с самогестеда на
управляемую СУБД, там из коробки восстановление на любой момент времени
(PITR через WAL-архивы), автоматические бэкапы (первая и каждая седьмая
полные, промежуточные инкрементные) и реплика для снятия бэкапа без нагрузки
на мастер. Цена, как считали раньше, ~7 200 ₽/мес — дороже ВМ.

**YandexGPT / Qwen / DeepSeek в AI Studio** — доступны модели с ценами от
0,1 ₽/1000 токенов (Alice AI LLM Flash, gpt-oss-20b) до 1,2 ₽ (YandexGPT Pro 5).
Для пакетной обработки есть отдельный режим (batch), обычно дешевле
синхронного. Это альтернатива зарубежным провайдерам, которые из YC
недоступны (OpenAI/Anthropic блокируют по гео) — важно, если агент когда-нибудь
переедет в YC.

**Перевод текста** — тарифицируется по символам; у тебя уже есть Google Translate
через `YANDEX_CLOUD_API_KEY`, так что это продублировано.

**Lockbox** — управление секретами. Сейчас ключи лежат в `.env` на VDS;
при росте числа сервисов Lockbox даёт централизованное хранение с ротацией.

**Cloud Logging** — централизованные логи. Полезно, когда cron-задач станет
больше и понадобится их мониторить не по serial console.

## Итоговые рекомендации

| Задача | Рекомендация | Стоимость |
|---|---|---|
| Векторный поиск | pgvector в существующем PostgreSQL | 0 ₽ сверху |
| Визуализация | DataLens (1 место бесплатно) | 0 ₽ |
| Библиография | `core.document` + Search API (отложенный режим) | 30,5 ₽/1000 зап. |
| Obsidian | локально; статика через Object Storage при необходимости | копейки |
| Пакетная LLM-обработка в YC | AI Studio batch-режим | от 0,1 ₽/1000 ток. |
| Векторизация (если нужна) | AI Studio embeddings | 153 ₽ разово |

Три сервиса стоит включить почти сразу: **pgvector** (векторный поиск в
существующей базе), **DataLens** (бесплатная визуализация вместо GitHub Pages)
и **Search API в отложенном режиме** (обогащение библиографии и региональный
Wordstat). Все три — либо бесплатны, либо стоят копейки, и не требуют новых
кластеров.

OpenSearch, Managed PostgreSQL и Managed ClickHouse — не нужны: первый дорог
для 689 страниц, второй дороже самогестеда, третий избыточен для текущих
объёмов (2.4 ГБ в PostgreSQL).

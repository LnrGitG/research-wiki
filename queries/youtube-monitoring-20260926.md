# Мониторинг YouTube: каналы для регулярного обхода (26.09.2026)

Отклонён сторонний набор `ZeroPointRepo/youtube-skills` (платный TranscriptAPI за транскриптами,
которые наш собственный навык `media/youtube-content` тянет бесплатно). Обход построен на публичных
RSS-фидах каналов: без API-ключа, без квоты, без сторонних сервисов. Артефакты: скрипт
`scripts/youtube_monitor.py`, список `data/yt_channels.csv`, состояние `data/yt_state.json`.

## 1. Состояние доступа к YouTube Data API v3

| Проверка | Результат |
|---|---|
| `GCP_API_KEY` из `.env` (53 знака, вида `AQ.Ab8…`) | **не API-ключ**: Data API отвечает `401 — API keys are not supported by this API. Expected OAuth2 access token` |
| ADC `~/.config/gcloud/application_default_credentials.json` (type `authorized_user`) | токен выдаётся, но Data API отвечает `403 — Request had insufficient authentication scopes` |
| Публичный RSS-фид канала `youtube.com/feeds/videos.xml?channel_id=…` | **работает с VPS без ключа**, отдаёт последние 15 видео с датами и названиями |
| Навык `media/youtube-content` (`youtube-transcript-api`) | **работает с VPS**: транскрипт по ссылке получен (проверено на живом видео) |

Вывод: для регулярного обхода ключ не нужен — RSS закрывает задачу «что нового на канале».
Data API v3 понадобится только для поиска и метаданных каналов; чтобы его включить, нужно создать
в проекте `integral-vim-508405-t0` обычный API-ключ (формат `AIza…`) и включить YouTube Data API v3
(бесплатная квота 10 000 юнитов в сутки), либо переавторизовать ADC с областью `youtube.readonly`.

## 4. Режим обхода

```
python3 scripts/youtube_monitor.py                 # последние видео по всем каналам
python3 scripts/youtube_monitor.py --new-only      # только то, чего не было в прошлый раз
python3 scripts/youtube_monitor.py --stale-days 60 # пометить каналы без публикаций больше 60 дней
```

Рекомендуемая частота — раз в неделю (например, понедельник 09:00 UTC) с доставкой отчёта
`--new-only` в Telegram: 11 каналов × 15 видео, расход квоты — нулевой, время — около 5 секунд.
Отдельно в отчёт стоит включать `--stale-days 60`, чтобы ловить замолчавшие каналы (как только что
случилось с Минстроем и НОСТРОЕМ) и заменять их в списке.
